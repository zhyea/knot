## 7. 本轮新增发现（安全类，需决策）

### 🔴 P0-1 网关插件日志全量落 requestBody / responseBody

所有内置日志插件把上下文塞进 payload，最终由 `LoggingPluginEventSink.emit()` 用 `log.info` **全量 JSON 输出**：

```
knot-plugin/.../runtime/LoggingPluginEventSink.java:15   log.info("plugin-event ... payload={}", JsonKit.toJson(event.payload()))
```

| 插件 | 落盘字段 |
|---|---|
| `GatewayRequestLoggingPlugin.java:44` | `requestBody` |
| `GatewayResponseLoggingPlugin.java:39` | `responseBody` |
| `GatewayErrorLoggingPlugin.java:40` | `requestBody` |
| `UpstreamRequestLoggingPlugin.java` | `requestBody` / `response` |
| `UpstreamResponseLoggingPlugin.java:39` | `responseBody` |

风险：网关转发的是 LLM 流量 —— `requestBody` 含用户 prompt（可能含业务敏感数据），
`responseBody` 含模型输出，`routing` snapshot 含 provider/模型路由信息。这与项目既定的
「`JsonKit` 解析失败只输出摘要 `len=N, first=X`」的日志纪律**直接冲突**。
2026-09-22 已记录 `LoggingPluginEventSink.java:15` 一条，本轮确认**整条插件日志链都是同一问题**。

建议：payload 输出前按字段分级（默认只留 `ruleCode/protocol/traceId/stage`），
`requestBody`/`responseBody` 走摘要（复用 `JsonKit.digestForLog()`）或加 `knot.plugin.log.payload=off` 开关。

### 🟠 P1-1 凭据加密密钥有明文默认兜底

```
knot-admin/src/main/resources/application.yml:51
  encryption-key: ${KNOT_CREDENTIAL_ENCRYPTION_KEY:knot-dev-credential-encryption-key}
```

未注入环境变量时，用**硬编码在仓库里的公开字符串**做 AES-256-GCM 主密钥 → 凭据等同明文，
且换密钥后旧密文解密抛异常会打挂接口。建议：去掉默认值，缺参即启动失败（fail-fast）。

### 🟠 P1-2 默认重置口令硬编码 `12345678`

```
knot-service/.../service/UserService.java:33   private static final String DEFAULT_RESET_PASSWORD = "12345678";
  :71   登录时若是该口令 → 走 forcePasswordChange（强制改密）
  :95   禁止把密码改成该口令
  :256  resetPassword() 重置为该口令
```

有强制改密流程兜底，风险可控；但弱口令常量写死在代码里且无法配置。建议：改为配置项 +
重置时随机生成一次性口令。
