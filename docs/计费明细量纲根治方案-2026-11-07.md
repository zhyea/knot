## 1. 根源定性

> **「计费量」在模型里是一个裸 `long`，字段名固定叫 `tokens`，量纲只存在于计算过程的局部变量，
> 从未进入数据契约；下游只能靠 `type` 字符串猜它是 token、秒还是张。**

一个根源，三层失效：

| 层 | 失效点 | 实测证据 |
|---|---|---|
| 命名 | `NormalizedUsageDetail.tokens` 名为 token，实为「计费量」（token / 张 / 秒 / 次） | `knot-adapter/.../model/usage/NormalizedUsageDetail.java:13-16`；`docs/knot_extend-billing-detail-type-取值盘点-2026-10-12.md:44` 已明文承认 |
| 结构 | `unitSize` 在 `detail()` 里被消费后就丢弃，只剩被放大 1e6 倍的 `price`。下游拿到 `price=800000.0` 无从还原「0.8/秒」 | `AbstractBillingModeCalculator.java:46-48,69-80,99-106`；`BillingUnitEnum.java:56-64` |
| 传递 | `BillingViewMsgDto.resolveMode()` 靠 `type` 反推 `billing_mode`（只认 `TokenUsageDetailKind`，视频下为 null）；消息里根本没有 `unit` 字段；`rule_code`/`pricing_plan` 在唯一调用点恒传 `null` | `BillingViewMsgDto.java:39-73`；`GatewayTrafficMsgDto.java:343-348` |

**不是根因的**：`total_tokens = 0` 是正确口径（`NormalizedUsageSerializationTest.java:22`「视频按秒计费时 total_tokens 合法就是 0」）；`cost = quantity × price ÷ 1e6` 恒等式有守门（`VideoBillingModeCalculatorTest.java:733-763`）。这两条不能改。

**规范已经反向固化了错误**：`docs/gateway-traffic-msg-dto-field-reference-2026-10-29.md:221,231` 把两个字段都释义成 token；`docs/gateway-warehouse-data-model-2026-10-17.md:119` 数仓列名也叫 `tokens`。按 `00-core.md` 铁律 9（规范与代码冲突以代码为准并回写），改完代码必须回写活文档。

## 2. 设计原则

1. **量纲随量走**：`quantity` 与 `unit` 必须在同一个 record 的同一行，任何构造出口都不能只给量不给单位。
2. **名字说真话**：不保留 `tokens` 这个骗人的名字。按项目红线「无历史包袱、一次做干净、不留兼容兜底」，**不双写、不回填**。
3. **一处收口**：`AbstractBillingModeCalculator.detail()` 已是唯一构造出口（`60-business-rules.md:12` 认证）。改类型 + 改这一个方法 + 换调用点参数，14 处调用不动业务逻辑。
4. **单一事实源**：`unit` 取 `BillingModeEnum.normalizeUnit()` 这个既有唯一出口（`BillingModeEnum.java:99-102`），不新造概念、不让 `unitSize` 与 `unit` 两处各自推导。
5. **复算式不变**：`cost = quantity × price ÷ 1e6` 保持。`price` 不改名、「每百万单位单价」口径也不变 —— `60-business-rules.md:13,26` 与全部守门测试只需把 `tokens` 换成 `quantity`，公式与断言一个字不动。
6. **不做无收益的对齐**：数仓列名 / 旧文档字段名不是事实标准，改动判据只有「语义是否清晰、代码是否自洽」。

## 3. 目标契约

改造前（本次日志）：

```json
"billing": {
  "rule_version": "v1", "total_tokens": 0, "total_cost": "4.8", "currency": "USD",
  "detail": [{ "type": "VIDEO:720P", "tokens": 6, "cost": "4.8", "price": "800000.0" }]
}
```

改造后（**schema 保持 `knot.gateway.traffic/1.1`**，见 §5）：

```json
"billing": {
  "rule_code": "BR-KLING-3T", "rule_version": "v1",
  "billing_mode": "VIDEO", "pricing_plan": "DIMENSION_TIERED",
  "total_tokens": 0, "total_cost": "4.8", "currency": "USD",
  "detail": [{
    "type": "VIDEO:720P",
    "quantity": 6, "unit": "PER_SECOND",
    "cost": "4.8", "price": "800000.0"
  }]
}
```

| 旧 | 新 | 说明 |
|---|---|---|
| `detail[].tokens` | `detail[].quantity` | 计费量，单位由同行 `unit` 给出 |
| — | `detail[].unit` | `BillingUnitEnum.code()`（`PER_SECOND` / `1M_TOKENS` / `PER_IMAGE` / `PER_REQUEST`…） |
| `detail[].price` | **不变** | 「数量 / 单位 / 价格」三元组合已自解释；口径仍是每百万单位单价 |
| `detail[].type` | 不变 | 开放集合（`VIDEO:720P` 等），不枚举化 |
| `detail[].cost` | 不变 | 十进制普通字符串 |
| `billing.total_tokens` | 不变 | **仅为 token 口径**，与 `detail.quantity` 不可比、不可相加；契约文档钉死 |
| `billing.billing_mode` | 由结果携带 | 删掉按 `type` 反推的 `resolveMode()` |
| `billing.rule_code` / `pricing_plan` | 由结果携带 | 修掉 `GatewayTrafficMsgDto:347` 恒传 null |

**不下发 `unit_size`**：有 `unit` 即可由 `BillingUnitEnum.unitSizeOf()` 推导，同一事实不在契约里写两遍；且复算式 `quantity × price ÷ 1e6` 不依赖它。下游若要还原原始单价：`unit_price = price × unit_size ÷ 1e6`。

**两出口同步**：`NormalizedUsageDetail` 同时服务 `knot_extend.billing`（camelCase：`quantity`/`unit`/`price`，见 `KnotExtendPayload.java:23-24`）与 Kafka `billing.detail[]`（snake_case，见 `BillingViewMsgDto.java:83-86`）。改 record 两个出口一起变，这正是「一次做干净」的机会。

## 8. 明确不做

- **不改 `detail[].price`**：「数量 / 单位 / 价格」三元组合已足够清晰；改成 `price_per_million` 属**负优化**（robin 2026-11-07）。会无谓破坏 `knot_extend.billing` 响应契约、改掉 `60-business-rules.md` 公式与一批断言，而收益只是「跟一个没人消费的数仓列名对齐」。
- **不把 `type` 改成枚举**：`VIDEO:720P` 是开放集合（`docs/...取值盘点:49`），`TokenUsageDetailKind` 只覆盖 token 六值。量纲由 `unit` 表达，不靠 `type`。
- **不改 `total_tokens`**：它语义正确（真 token 总量），改了反而丢信息。只改文档释义。
- **不双写、不做兼容兜底、不回填存量、不做 schema 分流**：数据未落数仓、无消费方，一次做干净。
- **不下发命中档位键**（`720P:AUDIO` vs `720P`）：属「复算可验证性」另一议题，`usage.attributes` 已给 `resolution`/`sound`，另立批次评估 `detail.dimension_key`。
- **不处理币种**：日志 `currency=USD` 与 `docs/Kling3.0Turbo对接方案-2026-10-27.md:72` 的「¥0.8/秒」不一致，是**配置核对**问题（对 `kb_billing_rules.currency` 与供应商账单），不是代码缺陷，不进本批次。
