# knot 跨节点缓存与 Redis 需求梳理

> 扫描范围：`knot-server` 全部 8 模块的 `src/main`。日期 2026-10-15。
> 上一版（2026-10-14）漏了 `knot.outage.*`，本版补上；同时修正一处过时引用（见 §6）。

## 1. 结论速览

**真正需要 Redis 的只有 3 处，且代码全部已实现，默认都是 `caffeine`——多节点部署时切开关即可。**
其余缓存点共享了没有收益，只有 DB 压力与序列化成本。

| # | 位置 | 开关 | 不切的后果（不是变慢，是算错） |
|---|---|---|---|
| A1 | `traffic` 频控 / 额度计数 | `knot.traffic.store=redis` | 实际限额 = 配置限额 × 节点数 |
| A2 | `load` 最少负载在途 gauge | `knot.load.store=redis` | 只看本节点在途，选路把流量压到同一模型 |
| A3 | `outage` 异常摘除状态 | `knot.outage.store=redis` / `fallback` | 各节点各摘各的，坏模型仍被部分节点继续打 |

## 2. 判定口径（三分类）

| 类 | 判据 | 处置 |
|---|---|---|
| **A · 运行时共享状态** | 值由**多节点的请求共同累积或共同决策**；单节点视图会让语义错误 | 必须 Redis |
| **B · 只读配置副本** | 真源在 DB，缓存只是副本；各节点独立过期即最终一致 | 进程内 Caffeine |
| **C · 纯派生结果** | 由输入确定性算出，各节点算出来必然相同 | 进程内 Caffeine |

判据的关键不是"数据一不一致"，而是**"不一致会不会让行为出错"**。B 类不一致只是生效时刻不同（秒级~分钟级），可接受；A 类不一致是算错（额度放大 N 倍），不可接受。

## 3. A 类详解（必须跨节点共享）

### A1 频控 / 额度计数
- 接口 `traffic/TrafficCounterStore.java`
- 实现 `CaffeineTrafficCounterStore.java` / `RedisTrafficCounterStore.java`（Lua 原子）
- 装配 `TrafficCounterConfiguration.java:53,64`（`@ConditionalOnProperty` 二选一）
- 配置 `application.yml:33-43`；`key-prefix` 用于多环境隔离，`zone` **多节点必须一致**（否则日/月窗口边界不齐）
- 依赖 `knot-gateway/pom.xml:51-54`，注释已说明不切时不建立连接（RedisTemplate 惰性初始化）

### A2 最少负载在途 gauge
- 接口 `load/ModelLoadStore.java`；实现 `CaffeineModelLoadStore` / `RedisModelLoadStore`
- 装配 `ModelLoadStoreConfiguration.java:32,44`
- 语义是**可增可减的 gauge**（`enter` / `leave`），与 A1 的窗口单调计数不同，因此独立建抽象（依据 `docs/design/routing-least-load-design.md:75`）
- Redis 挂了 `get` 返 0（fail-open 视为不拥塞），不阻断选路

### A3 异常摘除状态（上一版遗漏）
- 接口 `outage/TargetOutageStore.java`；实现 `CaffeineTargetOutageStore` / `RedisTargetOutageStore`（Hash + Lua）/ `FallbackTargetOutageStore`
- 装配 `OutageStoreConfiguration.java:37,49,64`，**三档**：`caffeine`（默认）/ `redis` / `fallback`
- 带上窗口、冷却、探活租约，是**带状态机的条目**，故不与 A1/A2 复用（见 `TargetOutageStore.java:8-16`）
- `fallback` 档是**多节点推荐**（`OutageStoreConfiguration.java:57-62`）：Redis 优先，抖动时降级 Caffeine 保住摘除能力，恢复后回灌仍摘除中的条目（`FallbackTargetOutageStore.java:238-264`）
- 固有限制：降级期间的窗口计数/探活租约会丢失；要求严格一致应选纯 `redis` 档 + 外部保证 Redis 高可用
- 设计依据 `docs/design/routing-ejection-design.md:82-111`，风险条目 §14.1 明写 "caffeine 模式是单实例视图"

## 4. B 类（本地即可，但缺失效广播）

| 缓存点 | 位置 | 节奏 |
|---|---|---|
| 路由 / 模型 / 池 / 供应商 / 凭据 / 频控策略 / 计费规则（16 项） | `service/GatewayDataService.java:46-61` | 写后 30s 异步刷新，10min 硬过期；计费规则命中 10min / 未命中 30s |
| 网关侧词库资源 | `service/ModerationWordResource.java:45` | 同上；取词异常 fail-open 成空列表 |
| 插件侧编译产物（自动机） | `knot-plugin/.../components/ModerationWordCache.java:38` | 按 `ModerationTerm.versionOf` 去重编译 |

**为什么不该搬进 Redis**：真源是 DB，搬过去要背上序列化、版本兼容、反序列化失败的额外复杂度，而这些 QPS 下 DB 扛得住（每个节点各自 30s 刷新一次，N 节点的 DB 压力是 N/30s，不是每请求）。

**真正的缺口是"没有跨节点失效通道"**：管理端改了模型绑定、停用了应用、改了额度或词库，各节点最长 10 分钟后才陆续生效，且生效时刻不齐。要做的是 **Redis pub/sub 广播 invalidate**（消息体只有键，不装数据），而不是把实体搬进 Redis。当前**未实现**。

## 5. C 类（本地即可，共享零收益）

- **粘性路由 hash 环**：`routing/StickyRouting.java:40`，纯函数结果，源码注释已写明"跨节点共享没有任何收益"
- **管理端登录态**：`knot-common/.../auth/JwtUtil.java`，JWT 无状态；`knot-admin/pom.xml` 无 spring-session 依赖，无需 session 共享

## 6. 修正：一处过时引用

上一版引用的 `gateway/moderation/ModerationConfigSource.java`（含 `invalidate()`）**在当前代码里已不存在**——网关 `moderation` 包已移除，词库缓存拆成网关侧 `ModerationWordResource`（资源副本）+ 插件侧 `ModerationWordCache`（编译产物）。结论不变（都是 B 类），但引用路径以本版为准。

## 7. 部署前必须补的配置（否则切了也白切）

1. **Redis 连接配置缺失**：全仓 `*.yml` 无 `spring.data.redis.*`。三个 Redis 实现都靠 Spring Boot 默认装配，`RedisTargetOutageStore.java:28` 明写"并配好 `spring.data.redis.*`"。不补就是连 `localhost:6379`。需补 `host / port / password / timeout`，一律走环境变量注入（与 `KNOT_DB_USERNAME` 同款口径）。
2. `knot.traffic.zone` 多节点必须配成同一个值（`application.yml:38`）。
3. `knot.outage.admin-api.token` 多节点必须配置（`application.yml:63`），未配时管理面只允许 loopback。
4. 三个 store 的 `key-prefix` 在多环境共用同一 Redis 时用于隔离。
