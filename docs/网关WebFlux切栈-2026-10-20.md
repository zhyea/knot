## 0. 结论

网关从 **Servlet（Tomcat + spring-webmvc）** 全量切到 **Reactive（Netty + spring-webflux）**，三批全部闭环：

| 批 | 内容 | 状态 |
|---|---|---|
| 1-A | WebClient 换 RestClient（含流式）、鉴权接口改 `HttpHeaders`、连接池参数归一 | ✅ |
| 1-B | 链路 `CompletableFuture` → `Mono`、ThreadLocal 拆净、退避改 `Mono.delay` | ✅ |
| 2 | 切 Netty、清 Servlet API、流式改纯 `Flux<DataBuffer>`、multipart 改 `FilePart` | ✅ |
| 3 | 全量门禁 + 十场景真启冒烟 | ✅ 10/10 |

门禁数据见 §5。**robin 已于 2026-10-20 11:24 批准提交。**

## 1. 决策与范围

- **动机**（robin 全选）：流式 SSE 并发承载 / 上游等待与退避不占线程 / 反压与内存 / 统一技术栈用上 WebClient。
- **阻塞源处置**：MyBatis（JDBC）与 `RedisTemplate` **不换** R2DBC / ReactiveRedis，保持阻塞、用 `Schedulers.boundedElastic()` 隔离。
- **反压**：Reactor 的 `Flux` 是「拉模式 + 64 项缓冲」——消费慢时自动向上游传导减速信号，无需像 Servlet 时代那样自己控速；网关把上游 `Flux<DataBuffer>` 直通给 Netty 写出，中间不落全量缓冲。

## 2. 各批落地

### 批1-A / 1-B
- `UpstreamRestClientConfiguration`（HC5）删除，新增 `UpstreamWebClientConfiguration`（ConnectionProvider + HttpClient + WebClient）。
- Duration 的 0/负必须归一成 `null`（`unboundedAsNull`）——传 0 会被 Netty 当「立即超时」。
- `AbstractGatewayRequestTemplate.handle/handleMultipart/handleMap` 与 `proxy` 抽象返回 `Mono`；`attemptCandidates` 索引递归 + `ScanState`。
- 追踪上下文从 ThreadLocal 改为 **Reactor Context**（`GatewayTraceContext.CONTEXT_KEY`），响应读写改 `GatewayHttpExchange` 显式传参。
- 顺手修两处既有缺陷：`UpstreamProxyClient` 异步线程读到随机 traceId；gateway pom 补 `jjwt-impl`/`jjwt-jackson` runtime。

### 批2（切容器）
- 移除 `spring-boot-starter-web`；`knot-service` 的传递依赖用 `<exclusion>` 挡住（否则 Boot 按 SERVLET 启动）。
- 8 控制器 + 2 Filter + 2 个 advice/CORS 配置全翻：`DeferredResult`→`Mono<ResponseEntity<>>`、`OncePerRequestFilter`→`WebFilter`、`WebMvcConfigurer`→`CorsWebFilter`、`@ControllerAdvice`→`@RestControllerAdvice`。
- 流式改纯 `Flux<DataBuffer>`（`ProxyStreamingFlux` + `GatewayStreamingResponse`），废弃 `ProxyStreamingBody`。
- **推翻批1 结论**：调度从 `CallerRunsPolicy` 改 `Schedulers.boundedElastic()`——Netty 下池满任务回落到 event loop 就地阻塞 I/O 线程，是灾难。
- multipart 入站 `MultipartFile` → `FilePart`，上送走 `MultipartBodyBuilder.asyncPart` 直连上游，不落内存不落盘。
- MDC 只在阻塞段任务线程上绑（`MdcContextSupport`）——event loop 上写会串号。

## 3. 踩坑全集（按「单测是否能发现」排序）

| # | 坑 | 根因 | 修法 | 守卫 |
|---|---|---|---|---|
| 1 | multipart 端点 400 `Required query parameter 'prompt' is not present` | WebFlux 的 `@RequestParam` **只绑查询参数**（SPR-16190 未修），Servlet 栈却能取表单值 | 全改 `@RequestPart` | `GatewayImageControllerMultipartBindingTest` 守卫① |
| 2 | multipart 端点 415 `bodyType=FilePart[]` | `RequestPartMethodArgumentResolver` 不认数组（只认 `FilePart`/`List`/`Flux`/`Mono`），数组掉进「单 part 当整体 body 解码」分支 | `FilePart[]`→`List<FilePart>` | 守卫② |
| 3 | multipart 端点 415 `bodyType=Integer` | `@RequestPart` 走 HttpMessageReader 管线，默认 codec 只有 `StringDecoder.allMimeTypes()` 兜得住无 Content-Type 的 part | 数字/布尔字段绑 `String`（上送字节与旧实现逐字节一致） | 守卫③ |
| 4 | 网关启动 `ClassNotFoundException: jakarta.servlet.http.HttpServletRequest` | `CurrentAuth` 被 `ProviderService` 构造器硬依赖，`@ConditionalOnClass` 挡不掉（只会把 `NoClassDefFoundError` 换成 `UnsatisfiedDependencyException`） | 改只依赖 `RequestAttributes` 接口，彻底 Servlet-free | 真启 |
| 5 | 同上 | `MissingRequestHeaderException` 父类链是 `ServletRequestBindingException → jakarta.servlet.ServletException`，Netty 栈反射扫描即炸 | advice 里改抓 `ServerWebInputException` 等响应式类型 | 真启 |
| 6 | 响应头静默丢失 | 响应读写原走 ThreadLocal，Reactor 线程模型下取不到，**且不报错** | `GatewayHttpExchange` 显式传参 | 真启 s9 断言 |
| 7 | 守卫测试假绿 | `@PostMapping` 是 `@RequestMapping` 元注解，`getAnnotation` 恒 null，扫描被整段跳过 | 改 `AnnotatedElementUtils.findMergedAnnotation`；必错探针复验 | 探针 |

**共同教训（坑 1/2/3）**：Servlet 的参数绑定语义（ConversionService + MVC 专用 resolver）在 WebFlux 侧**全部不存在**，切栈必须逐参数核对形态，不能照抄签名。三者单测全部哑火，只有真启 multipart 请求才暴露——所以 s10 的四层注解契约守卫 + 真启断言是双保险。

## 4. 类名迁移对照表

旧设计文档（`docs/design/*`、`knot_extend-输出规范` 等）里的类名按此表翻译：

| 旧（Servlet 栈） | 新（Reactive 栈） |
|---|---|
| `ProxyStreamingBody`（`StreamingResponseBody`） | `ProxyStreamingFlux` + `GatewayStreamingResponse`（`Flux<DataBuffer>`） |
| `UpstreamRestClientConfiguration`（HC5） | `UpstreamWebClientConfiguration`（reactor-netty） |
| `gatewayAsyncExecutor`（`ThreadPoolTaskExecutor` + CallerRunsPolicy） | `gatewayBlockingScheduler`（`newBoundedElastic`） |
| `DeferredResult<Object>` + `spring.mvc.async.request-timeout` | `Mono<ResponseEntity<Object>>` + `knot.gateway.upstream.request-budget`（`Mono.timeout` → 504） |
| `MultipartFile` / `MultipartFile[]` | `FilePart` / `List<FilePart>` |
| `OncePerRequestFilter` | `WebFilter` |
| `@ControllerAdvice` + `@ResponseBody` | `@RestControllerAdvice` + `ResponseEntity` |
| `RestClient` | `WebClient` |
| `HttpServletRequest/Response` | `ServerHttpRequest/Response`（`GatewayHttpExchange` 封装） |
| `AsyncRequestTimeoutException` | `java.util.concurrent.TimeoutException` |
| MockMvc 测流式（`asyncStarted()` + `getAsyncResult()`） | 直接调方法 + 反射契约检查（`WebTestClient.bindToController` 的 codec 管线跑不通 multipart） |

`asyncExecutorThreads` 配置项**名字未改**，语义从「线程池大小」变为「boundedElastic 线程数」，仍是「同时在途阻塞段上限」。

## 7. 边界与遗留

- **admin 仍跑 Servlet（Tomcat）**：有意为之，本次范围只含网关。admin 的 `AuthInterceptor` / `AdminAuthorizationInterceptor` 继续用 `jakarta.servlet`。
- **`OperationLogAspect` 保留 `@ConditionalOnClass`**：它无 bean 依赖它，网关控制器无 `@OperationLog`，条件装配安全（与 `CurrentAuth` 的区别见坑 4）。
- **摘除 B5 的 Redis Lua 改动仍未真启验证**（本机无 Redis）——上 Redis 档前须真回归，与本次切栈无关。
- `.workbuddy/tmp/` 留有早期分析用的 Spring 源码抽取件与探针日志（`StreamingResponseBodyReturnValueHandler.java` 等），属 scratch，可按需清理。
- 历史设计文档（`docs/design/routing-*.md` 等）按「存档不改」处理，类名引用用 §4 对照表翻译。
