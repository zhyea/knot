## 一、P0：JEV 计费裁判前端链路未闭合（端到端功能缺失）

**证据链（三处互证）：**

```
① 后端端点在线    knot-admin/.../RoutingRuleController.java:195   @PostMapping("/{id}/test/billing-verdict")
② 前端封装在线    knot-front/src/api/routing.ts:241                export function testRoutingRuleBillingVerdict(...)
③ 调用方缺席      全 src grep "testRoutingRuleBillingVerdict"  → 仅出现于 ② 自身
                  全 src grep "RoutingBillingVerdictPanel"      → 仅出现于该 .vue 自身
```

- `RoutingRuleTestDrawer.vue:244` 的 import 只引了 `listRoutingRuleDebugProtocols, testRoutingRule, testRoutingRuleStream`，
  **没有** `testRoutingRuleBillingVerdict`；`:985` 的测试主流程 `await testRoutingRule(...)` 之后也没有触发裁判。
- **为什么 669 个单测 + vue-tsc + vite build 全绿也没拦住**：
  纯前端「接线缺失」不在任何编译/类型/单测的作用域内；`vue-tsc` 只检查语法与类型，孤儿组件不是错误。
- **落地坐标**：在 `RoutingRuleTestDrawer.vue` 里，于 `:985` 的测试响应处理之后调用 `testRoutingRuleBillingVerdict`，
  并把结果喂给 `RoutingBillingVerdictPanel.vue`（其 props 契约已就绪）。补 import 于 `:244`。
- 建议同时加一道**守卫**：CI 或巡检脚本把「零引用 .vue 组件」当错误，防止再次出现（本仓库已有可复用脚本 `audit_orphan.py`）。

## 二、P1 项

### 2.1 协议能力双份维护（数据/口径漂移风险）

| 位置 | 集合大小 | 独有项 |
|---|---|---|
| `knot-adapter/.../OpenAiCompatibleRequestAdapter.java:24` `PROTOCOLS` | 15 | `CUSTOM` |
| `knot-service/.../RoutingRuleService.java:92` `DEBUGGABLE_PROTOCOLS` | 15 | `DECISIONS` |

- 两份集合 **14 项完全相同**（CHAT_COMPLETIONS / RESPONSES / MESSAGES / COMPLETIONS / EMBEDDINGS / IMAGE_*3 / AUDIO_*3 / VIDEO_GENERATIONS / RERANK / MODERATIONS），
  各自私有的一项差异是**合理**的，但「完全相同部分」存在**双写**风险：新增协议漏改一处 →
  要么管理端抽屉不可测（漏 `DEBUGGABLE`），要么抽屉允许挑但该 adapter 不支持（漏 `PROTOCOLS`），且**无编译错误、无单测报错**。
- `knot-service` 已依赖 `knot-adapter`（pom.xml:34），技术上可收敛。建议二选一：
  - **A（推荐）**：在 `ModelApiProtocolEnum` 上用属性声明能力（`openAiCompatible` / `debuggable` / …），两处都从枚举派生；
  - **B（轻量）**：`OpenAiCompatibleRequestAdapter.PROTOCOLS` 暴露为 public 常量，service 侧以「排除法」表达自己多支持的一项（`DECISIONS`）。
- ⚠ 是否改动属架构决策，本次**未动**，请 robin 定。

### 2.2 测试缺口：28 个核心类无同名测试

按模块分布：`knot-service` 24、`knot-admin` 3、`knot-gateway` 1。其中体量最大的几个：

| 类 | 行数 | 备注 |
|---|---|---|
| `RoutingRuleService` | 1,173 | 仓库最大 Java 文件，**零直接单测** |
| `BillingService` | 872 | 计费三级回退核心（仅有 `BillingServiceRestoreTest` 侧写） |
| `ModelService` | 725 | — |
| `GatewayRequestHandler` | 587 | 网关主链路,knot gateway 模块用例集中在 Kafka/协议/流式的边界类 |

> 口径说明：判据是「不存在同名 `*Test` 且正文未提及该类名的测试」，属**保守判定**——
> 这些类可能被 Controller 契约测试间接覆盖。结论是「缺少针对性单测」，不等于「零覆盖」。
