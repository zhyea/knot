## 二、执行顺序（严格按批，每批独立验证）

```
批次 1（P0 全部）   → 前端 build + 冒烟
批次 2（先 11 后 8）→ 后端 test + 前端 build
批次 3（9）         → 后端 test（含新增校验用例）+ 前端 build
批次 4（7）         → 后端 test + 前端 build
批次 5（10）        → 待拍板后执行
```

**为什么 9 要早于 8：** 凭证类型只影响单个表单；计费 mode×unit 一旦拆掉前端约束而没有后端校验，
会产生「模式 TOKEN + 单位 PER_IMAGE」这类脏数据，属数据面风险。

**为什么 7 放最后：** 它是唯一需要后端新增响应模型的项，且要复用 `RoutingRuleService` 现有私有方法
（`defaultRequestBody:412-446`、`fillDefaultPromptFields:448-465`、`buildGatewayTestPath:514-532`），
涉及把一个 private 方法族提成共享能力，改动面最大，应放在前端已稳定之后。
