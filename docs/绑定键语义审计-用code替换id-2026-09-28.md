# 绑定键语义审计：哪里还适合用 code 替换 id

日期：2026-09-28　审计范围：`knot-admin/src/main/resources/db/schema.sql`（52 表）+ 本机库（MariaDB 10.6.3）+ 33 个 mapper XML

## 一、判定标准

绑定键从 id 改 code 只在这四类同时成立时划算：

| 条件 | 说明 |
|---|---|
| 目标表有**唯一**业务码 | 否则 code 无法当外键（本机库已逐表 `SHOW INDEX` 核对） |
| 目标是**主数据/配置**，不是流水 | 配置数据要能跨环境迁移、人工读、导出后可复用 |
| 引用是**单态**（目标表固定） | 多态列（`target_type` + `target_id`）无法统一 |
| 不在**热路径**或热路径已有缓存 | 网关热路径零 DB（GatewayDataService 缓存），风险主要落在缓存装载逻辑同步 |

## 二、建议清单

## 三、不建议改（含理由）

| 位置 | 理由 |
|---|---|
| `kb_routing_rule_targets.target_id`（562）、`kb_resource_traffic_policies.resource_id`（241）、`kb_plugin_bindings.scope_ref_id`（715）、`kr_plugin_execution_logs.scope_ref_id`（735） | **多态列**：目标类型由 `target_type`/`resource_type`/`scope_type` 决定（MODEL / POOL / APP / PROVIDER / GLOBAL），无法用单一 code 表达 |
| `kb_billing_rule_versions.rule_id`（590）、`kb_billing_rule_version_items.version_id`（609）、`ks_operation_log_details.log_id`（159） | **同表族父子键**，行业惯例用 id，改了只会增加 join 成本 |
| `kr_plugin_execution_logs`（0 行但会增长）、`ks_operation_logs`、`ks_scheduled_task_runs`（已冗余 `task_code`） | **流水/日志表**，量大且只用于追溯；runs 表已冗余 code，无需再改外键 |
| `ks_role_permissions.permission_id`（115）、`ks_api_permission_bindings.permission_id`（122）、`ks_user_roles.role_id`（63） | 权限码虽唯一，但 AuthInterceptor **默认拒绝**，改错即全站 403；收益（种子可移植）有限，建议单独排期并配全量冒烟 |
| `ks_users.user_id` 系列、`ks_departments.dept_id`（14/483） | username/dept_code 唯一但语义是登录名/组织名，用户体系用 id 更稳 |
| `kx_model_items.logical_model_id`（443） | 外部模型同步表，数据量随同步增长，保持 id |

## 四、核对过的本机库事实

- 候选主数据表唯一索引**与 schema 完全一致**：`uk_models_code`、`uk_logical_models_code`、`uk_apps_app_id`、`uk_model_pools_code`、`uk_routing_rules_code`、`uk_routing_consumers_code`、`uk_plugin_instances_code`、`uk_plugin_packages_code`、`uk_notification_templates_code`、`uk_departments_code`、`uk_sys_menus_code`、`uk_sys_permissions_code`、`uk_rate_limit_policies_code`、`uk_quota_policies_code`、`uk_roles_code`、`uk_sys_modules_code`。
- 数据量（本机库）：kb_models 10、kb_provider_model_mappings 4、kb_app_model_permissions 15、kb_app_credentials 3、kb_model_pool_items 4、ks_role_permissions 264、ks_api_permission_bindings 155 —— 业务侧表都是个位数到十位数，迁移代价低；权限侧两表上百行，是唯一需要谨慎的量级。
- 已完成项：供应商绑定 `kb_provider_accounts.provider_code`、`kb_billing_rules.provider_code`（2026-09-28）。

## 五、结论

真正值得动的是 **P0 一条（凭据表 app_id 同名歧义）** 和 **P1 三条（模型→账户、计费规则→统一模型）**。P1 改动面大且触及网关缓存装载，建议按 P0 → P1 分两批做；P2 可在任意空档顺手做。权限侧三表与所有多态列建议维持 id。
