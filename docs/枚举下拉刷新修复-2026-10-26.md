# DB 枚举下拉不刷新修复（2026-10-26）

## 一、缺陷

编辑 DB 枚举（枚举管理 / 模型族）后，回到列表打开编辑抽屉，下拉里看不到新增或改过的枚举值；
必须刷新列表（整页重载会重置前端模块状态）后，再打开抽屉才可见。

## 二、根因

枚举下拉 `EnumSelect` 的数据来自 `useEnums`（`knot-front/src/composables/useEnums.ts`），
它用一个**模块级 `CACHE`（按 category，TTL 5 分钟）**复用数据：

- `EnumSelect` 只在 `onMounted` 调 `loadOptions()`，命中缓存就**不发请求**；
- 缓存的刷新实际由**列表页**承担（`LogicalModelList` 的 `onMounted`、以及枚举编辑保存后的 `clearEnumCache()`）；
- 于是抽屉从不主动回源，只"借"别人填好的缓存 → 打开抽屉时缓存仍热就拿到旧值。

即责任放错了地方：刷新时机绑在列表页，而不是"打开表单"这个真正需要新鲜数据的时刻。

## 三、修复

### 前端（根因修复）

| 文件 | 改动 |
|---|---|
| `composables/useEnums.ts` | `loadOptions(force = false)`：`force=true` 时旁路 TTL 重新回源 |
| `components/common/EnumSelect.vue` | `onMounted` / `watch(category)` 改 `loadOptions(true)` |
| `components/model/ModelDiscountFormDialog.vue` | 挂载 `loadOptions(true)`（折扣类型） |
| `components/model/LogicalModelList.vue` | 挂载 `loadFamilyOptions(true)`（与下拉同口径，避免列表标签旧、下拉新） |
| `composables/useTimezone.ts` | 对外暴露的 `loadOptions` 包装为 `() => loadOptions(true)` |

`EnumSelect` 是通用下拉，一处改动覆盖全部宿主：`LogicalModelFormDrawer`（模型族）、
`BillingRuleFormDialog`（模型族）、`NotifyTemplateFormDialog`（渠道）、敏感词分类弹窗。
这些宿主**均为 `destroy-on-close`**，故"挂载"即"打开"，每次打开都会重新请求。

### 后端（吸收回源压力，注解方式）

| 文件 | 改动 |
|---|---|
| `knot-admin/pom.xml` | 新增 `spring-boot-starter-cache` |
| `knot-admin/.../config/CacheConfiguration.java`（新增） | `@EnableCaching` + `CaffeineCacheManager`，缓存名 `enumItems`，`expireAfterWrite=30s`、`maximumSize=64` |
| `knot-service/.../EnumConfigService.java` | 常量 `ENUM_ITEMS_CACHE="enumItems"`；`listByCategory` 加 `@Cacheable`；`create`/`update`/`deleteReturning` 加 `@CacheEvict(allEntries=true)` |

设计取舍：

- 单参数方法的默认 key 即 `category`，未显式写 `key`（`-parameters` 已开启，但省一层依赖）。
- 写操作用 `allEntries=true` 整表失效：DB 维护的分类仅 4 个，且变更方法入参是 id/entity、拿不到 category，
  逐键失效反而更易出错。
- 30s 窗口：走接口的改动由 `@CacheEvict` 即时失效；即使绕接口直接改库，最坏陈旧窗口 30 秒。
- **不动** `/api/enum-options`（代码枚举，来自内存注册表，无 DB 压力，与本缺陷无关）。

## 五、遗留与说明

- **未做手工 UI 回归**（未启 jar 真跑）：建议按原步骤验一次——枚举管理改模型族 → 回模型列表 → 开编辑抽屉，
  Network 应每次出现 `GET /api/system/enums/items/model_family`。
- 前端 `useEnums` 的模块级 `CACHE` 予以保留：非 force 路径仍可复用，`clearEnumCache()` 保持不动。
  真正修掉缺陷的是"打开即强制回源"，缓存退化为纯优化。
- 验证期间工作区存在**并发会话**改动（Kling 供应商支持）：`knot-common/BillingConfig`、
  `knot-adapter/TokenBillingModeCalculator`、`knot-front/BillingModeVideoConfig.vue` 等。
  中途两次构建失败均源于其写入中间态（编译期"找不到符号"/"case 标签重复"），与本次改动无关；
  当前 `vue-tsc` 残留的 5 个 `isVendorKling` 报错同样属于该文件，非本次范围。
