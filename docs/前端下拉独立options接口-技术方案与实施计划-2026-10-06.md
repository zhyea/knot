## 2. 原方案评估

### 2.1 做得好的地方

1. **增量迁移路径清晰**：先新增 options 接口 → 再逐个切前端 → 最后收紧列表返回，避免一次性破坏现有页面。符合本仓库"无历史包袱、全链路一次做干净"的既有纪律。
2. **风险识别齐全**：分页截断、语义不稳、前端过滤、性能、安全边界、权限区分、回显依赖、筛选耦合八条理由都成立，且都有代码证据支撑。
3. **`value` 固定契约 + `values` 回显 + `missingValues`**：直击"已选项不在第一页"和"静默伪造 `#id`"两个真实痛点。
4. **敏感字段隔离**：明确路由消费者 options 永不返回 `secretKey`，与现有"候选查询与敏感字段读取不应共用返回模型"诉求一致。
5. **独立权限码 + 临时映射 `*:list`**：与本仓库 `ks_api_permission_bindings` 默认拒绝（403）机制对齐。

### 2.2 必须修正 / 补强的点

| 编号 | 问题 | 修正建议 |
|---|---|---|
| R1 | **GET/POST 边界未定**。原方案多数资源用 POST，但模块/操作日志用 GET，且未说明何时用哪种 | **已拍板（决策 3）**：**有传参（keyword/values/filters/enabledOnly/分页）一律 POST；仅完全无传参（如操作日志聚合枚举）用 GET。** 即 `POST /api/{resource}/options` 为主路径，`GET /api/{resource}/options`（无 query、无 body）仅保留给 `operation-logs` 这类无输入聚合端点。 |

### 2.3 风险再评估

原方案第 8 节的风险项总体成立，补充两条：

- **R8（缓存与写后可见性）**：创建/启停/删除成功后须主动失效 options 缓存，否则保存后短暂"选项消失"。原方案提到但须列为**硬性验收项**（写操作返回后前端立即 `invalidate`，后端 Caffeine/Redis 键按资源+过滤维度失效）。
- **R9（权限迁移顺序）**：独立权限码未同步会导致下拉全空。本仓库 `ks_api_permission_bindings` 默认拒绝，**每个新 options 端点上线前必须 `gen_api_bindings.py` + `apply_bindings.py` 落绑定**，临时映射到 `*:list`。这是发布前置硬条件，不是可选项。

## 3. 技术方案（收敛版）

### 3.1 统一调用约定（决策 3 冻结）

- **默认 POST**：凡有传参（`keyword` / `values` / `filters` / `enabledOnly` / 分页）一律 `POST /api/{resource}/options`，body 见 3.2。
- **仅无传参用 GET**：完全无输入（如操作日志聚合枚举）才用 `GET /api/{resource}/options`（无 query、无 body）。
- 后端 `postQuery`/`PageQuery` 已是标准分页范式（`api/http.ts:119`、`TestRequestPresetController.java:30`），`OptionQuery` 与之平行即可。

### 3.2 请求 / 响应模型

```jsonc
// POST /api/{resource}/options
{
  "keyword": "gpt",
  "pageNum": 1,
  "pageSize": 20,            // 服务端上限 50，超额钳制
  "values": ["gpt-4o"],      // 回显，上限 100，超额拒绝
  "enabledOnly": true,
  "includeDeleted": false,
  "filters": { "logicalModelCode": "text.default" }  // 仅资源声明的白名单字段
}

// 响应 OptionPage<T>
{
  "list": [
    { "value": "text.default", "label": "通用文本（text.default）",
      "code": "text.default", "disabled": false,
      "meta": { "name": "通用文本", "status": "ENABLED" } }
  ],
  "total": 1, "pageNum": 1, "pageSize": 20,
  "missingValues": []
}
```

- `OptionItem` 必需字段仅 `value`/`label`；`code`/`meta` 只承载下拉确实需要的非敏感信息。
- **严禁返回**：credential、secretKey、完整 configJson、审计字段、大段描述。后端用 `@JsonIgnore` 或专用 VO（不复用列表 DTO）保证。
- `missingValues`：已选项不存在/无权限时返回，前端统一展示"已选项不存在或无权限"并阻止非法提交，**不得静默伪造 `#id`**。

### 3.3 后端分层（每资源）

```
Controller (参数校验 + 权限注解)
   └─ Service (业务可选性：启用/删除/可见/关联约束，SQL/Service 层完成过滤)
        └─ Mapper (专用查询方法，只查必要列；values 用批量 IN，≤100)
```

约束（采纳原方案 4.3，补强 R5）：
1. `list()` 与 `options()` 可复用状态校验/权限范围/label 组装小函数，但**不共用列表 DTO**。
2. options 默认只查必要列，过滤在 SQL 层；禁止先查实体再 Java 裁剪。
3. `values` 批量 `IN`，返回顺序按请求值或稳定业务排序。
4. 每资源 `XxxOptionQuery`（强类型 record），不接受任意 `Map`。
5. 路由消费者 / 供应商账户 options **永不返回 `secretKey`**。

### 3.4 前端改造

- **API 层**：每资源新增 `listXxxOptions(query)`（`src/api/*.ts`），不复用 `listXxx` 别名；`OptionQuery`/`OptionItem`/`OptionPage` 入 `src/types/index.ts`。
- **`RemoteEntitySelect` 改造**：
  - `loadFunction` 类型改为 options loader；默认 `pageSize=20`（组件层禁 500，服务端兜底 50）。
  - 把当前 `modelValue` 转 `values` 传给 options 接口（解决编辑回显不在第一页）。
  - `extraParams` → 受约束 `filters`（各资源 loader 构造白名单）。
  - 优先渲染 `item.label`；`labelFunction` 仅作迁移期兜底，最终删除对实体字段拼接的依赖。
  - 统一处理 `missingValues`（"已选项不存在或无权限"状态）。
- **value 语义矩阵（已按决策 1 冻结）**：

| 资源 | value | 提交 DTO 现有类型 | 备注 |
|---|---|---|---|
| 应用 | `id` | `appId: id` ✅ | 无需改 |
| 用户 | `id` | `userId: id` ✅ | 无需改 |
| 部门 | `id` | 表单 `deptId` | 需核对 |
| 角色 | `id` | `roleIds` | 需核对 |
| 供应商信息 | `code` | — | 新增 |
| 供应商账户 | `code` | — | 新增 |
| 统一模型 | `modelCode` | 表单 `logicalModelCode` ✅ | 一致 |
| 计费规则 | `code` | `billingRuleCode` | 需核对回显 |
| 供应商模型 | `modelCode` | ⚠️ 路由目标现用 `id`（R2，已拍板改 code） | **破坏性迁移：绑定改存 `model_code`** |
| 模型池 | `poolCode` | ⚠️ 路由目标现用 `id`（R2，已拍板改 code） | **破坏性迁移：绑定改存 `pool_code`** |
| 路由消费者 | `id` | `consumerIds: id` ✅ | 无需改 |
| 授权模块/菜单/权限 | `id` | — | 新增 options |

### 3.5 权限与缓存

- 每个 options 端点配独立权限码（`app:option:list` 等），迁移期临时映射 `*:list`；上线前用 `gen_api_bindings.py` + `apply_bindings.py` 落 `ks_api_permission_bindings`（硬前置）。
- options 按资源+过滤+权限上下文缓存 30~300s；关键字搜索不全局缓存。组件销毁/过滤变化取消上一次请求（避免乱序覆盖）。同资源并发请求共享 in-flight Promise。
- **写后失效**（R8）：创建/更新/删除/启停成功后主动失效对应 options 缓存键。

## 5. 验收标准（可操作）

**后端**
- 每个 options endpoint 在 7 种场景（无关键字/关键字/单值/多值/停用/删除/无权限）均有自动化测试。
- 响应仅含约定字段；JSON schema / 序列化断言保证无 `secret`/`configJson`。
- `pageSize>50` 钳制；`values>100` 拒绝。
- 业务过滤在 SQL/Service 层生效，不依赖前端二次过滤。

**前端**
- 所有 `RemoteEntitySelect` 的 `load-function` 指向 `*Options`；`rg` 扫描无 `load-function="list` 或同类直接传列表 API。
- >20 条实体可经关键字检索到非第一页。
- 编辑停用项正确回显；缺失值统一态且阻止非法提交。
- 路由目标切换模型/模型池后，过滤与 options 缓存正确失效。

**运行指标**
- 记录 options 请求 P50/P95、返回条数、`missingValues`、4xx/5xx、缓存命中率。
- 对比迁移前后列表接口响应体大小、DB 耗时、搜索请求数。
- 命中率 <99%、P95 >300ms、缺失值比例异常升高 → 优先查权限过滤、启用状态、`value` 类型一致性。

## 6. 风险清单（含缓解）

| 风险 | 等级 | 缓解 |
|---|---|---|
| R2 路由目标 `value` 语义冲突（决策 1 已冻结） | 高 | 已拍板改 `model_code`/`pool_code`；阶段一前置单列破坏性迁移（DROP/ADD + 数据回填），先迁移后切换 options |

| `filters` 透传任意字段 | 中 | 每资源强类型 `OptionQuery`（R5），禁通用 Map |
