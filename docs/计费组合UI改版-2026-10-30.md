# 计费组合 UI 改版（2026-10-30）

## 问题（robin 提出）

视频计费抽屉「计费组合」默认勾选「无声」不恰当——很多场景默认包含声音，只有在把无声单独列为计费项时才需要关注是否有声。

## 结论：不能取消 BASE，但「无声」这个词是错的

`BASE` 是取价回落链的终点，取消它「请求未声明音频开关」的调用就无价可取。但它的真实语义不是「无声专价」：

| 事实 | 位置 |
|---|---|
| `sound` 判定读请求体布尔开关（`generate_audio` / `audio` / `sound`…），**字段缺失即 false** | `VideoUsageFacts.java:52-53`、`:98` |
| 取价链 `档位:REFERENCE:AUDIO → 档位:REFERENCE → 档位:AUDIO → 档位` | `VideoBillingModeCalculator.java:307-323` |
| 有声加价有两条并行路径且会叠加：`:AUDIO` 单价（按秒）+ `surcharges[trigger=AUDIO]` 附加费（常数） | `VideoBillingModeCalculator.java:100-146`；`BillingModeVideoUsageConfig.vue:52-58` |

所以对默认带声的模型，客户端不传 `generate_audio` → 判无 → 命中 `BASE`。**这一列才是主力价**，把它叫「无声」并默认勾上，等于诱导配置者把便宜的无声音价填进主力列。

## 改动

1. **改名**：`BASE` 的界面文案 `无声` → **基础价**，占位改「留空用默认单价」；`BillingModeVideoUsageConfig` / 维度分档说明同步。
2. **四复选框 → 两个正交开关**（`ResolutionComboPicker.vue` 重写）：`有声单独定价` / `含参考输入单独定价`，**默认都关**（只渲染基础价一列）；基础价改为「必含」说明文字，不再是可勾选项。都开时自动补 `REFERENCE_AUDIO`。
3. **有声附加费互斥**：勾上有声单列时清空「音频直出附加费」并提示；历史配置两条并存时，附加费字段红字告警 + 保存期拦截。

统一落地口 `applyCombosChange()`（`utils/billingResolution.ts`）：归一 → 清被取消组合的行内价格 → 无「含参考」时回落 `quantityMode=OUTPUT` → 清附加费。原先两个宿主各写一份该逻辑，现收敛为一份。

## 兼容边界（不可动）

- 存量配置**无** `video.dimensionCombos` 字段 → 必须继续解释为**四列全开**（`LEGACY_COMBOS`）。若改成「仅基础价」，老配置的有声价 / 参考价会变成后端仍命中、界面上却看不见的静默收费。
- `DEFAULT_COMBOS`（新建 = `["BASE"]`）与 `LEGACY_COMBOS`（无字段回显 = 四码）是**两个常量**，守门测试断言二者不同。
- 非视频规则的 config 无 `video` 段时不再被塞四列默认值（否则 TOKEN 规则切 VIDEO 后残留四列，附加费冲突会误判）。
- 新建视频规则会落 `video.dimensionCombos: ["BASE"]`——这是必然的：不落字段回显就只能按历史全开。
