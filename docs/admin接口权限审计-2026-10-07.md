# knot-admin 对外接口权限审计

- 审计日期：2026-10-07
- 审计范围：knot-admin 模块全部 REST controller（40 个 controller 类、约 135 个 HTTP 端点操作）
- 审计目标：确认所有对外暴露的接口是否都经过权限验证（认证 + 接口级授权）

## 一、鉴权机制（三层防线）

| 层 | 实现 | 位置 | 行为 |
|---|---|---|---|
| 认证 | `AuthInterceptor` | `knot-admin/.../auth/AuthInterceptor.java:22` | 拦截 `/api/**`，校验 JWT Bearer；无 token → 401 |
| 接口级授权 | `AdminAuthorizationInterceptor` | `knot-admin/.../auth/AdminAuthorizationInterceptor.java:34` | 拦截 `/api/**`（除白名单），调 `validateApiAccess`，**默认拒绝** |
| 默认拒绝逻辑 | `AdminAuthorizationService.validateApiAccess` | `knot-service/.../service/AdminAuthorizationService.java:39` | `ks_api_permission_bindings` 无匹配 → 403；用户未持权限码 → 403 |

拦截器注册：`knot-admin/.../config/WebMvcConfig.java:28`
- `AuthInterceptor` 的 exclude：`/api/auth/login`、`/api/auth/force-password-change`、`/api/auth/logout`、`/api/health`
- `AdminAuthorizationInterceptor` 的 exclude：上述 4 个 + `/api/me/authorizations`、`/api/common/enums`

### 关键正确性证据
- 匹配语义为**精确相等**：`AdminAuthorizationMapper.xml:26` 用 `b.path_pattern = #{pathPattern}`（`http_method` + 模板路径，含 `{id}` 占位符），非前缀匹配。结合 Spring 传入的 `HandlerMapping.BEST_MATCHING_PATTERN_ATTRIBUTE`，`/api/users/{id}` 的绑定不会误匹配 `/api/users/{id}/status` 等相邻路径，**排除了越权误放行**。

## 二、覆盖范围核对结论

- ✅ **所有 controller 的 `@RequestMapping` 前缀均在 `/api/**` 下**（含 `/api`、`/api/docs`、`/api/system/*`），**没有暴露在拦截范围之外的裸奔接口**。
- ✅ **全部非白名单端点都已在 `ks_api_permission_bindings` 中绑定**。`data.sql` 共 190 条绑定记录（id 1–174 + 175–190 两段），覆盖所有 controller 端点，包括后加的 options 下拉、`/{id}/restore`、测试流式 `/{id}/test/stream`、`/{id}` 详情等。
- ✅ **无 actuator / context-path 等脱离拦截的额外暴露面**（admin 未引入 actuator starter，未配 `server.servlet.context-path`）。

## 三、白名单接口合理性评估

| 接口 | 方法 | 放行类型 | 评估 |
|---|---|---|---|
| `/api/auth/login` | POST | 公开（免认证+免授权） | ✅ 登录入口，合理 |
| `/api/auth/force-password-change` | POST | 公开 | ✅ 首次强制改密，合理 |
| `/api/auth/logout` | POST | 公开 | ✅ 登出，合理 |
| `/api/health` | POST | 公开 | ✅ 健康检查，合理 |
| `/api/me/authorizations` | GET | 仅认证（免接口级授权） | ✅ 防自锁死（注释已说明） |
| `/api/common/enums` | GET | 仅认证（免接口级授权） | ✅ 全站通用枚举字典（注释已说明） |

## 四、风险点与改进建议（均非阻断）

1. ⚠️ **API 文档接口的信息暴露面**：`/api/docs/openapi.json`、`/api/docs/changelog`（binding 54/55）会向持有 `api-doc` 权限的用户暴露完整 API 契约（内部路径、参数、model 字段）。需登录+权限，不算裸奔，但建议确认仅 ADMIN/DEV 角色持有该权限。
2. ⚠️ **两个"仅认证"白名单接口**：`/api/me/authorizations`、`/api/common/enums` 任何已登录角色均可调用。属设计意图，但建议知情：任一登录用户都能拉取全站枚举与自身权限快照。
3. ⚠️ **`validateApiAccess` 的 fallback 路径**（`AdminAuthorizationService.java:45-47`）：当 `BEST_MATCHING_PATTERN_ATTRIBUTE` 为空时，会用真实请求 URI（如 `/api/users/123`）查绑定，而绑定存的是模板路径（`/api/users/{id}`），会查不到 → **误 403（过度拦截，非安全漏洞）**。正常请求都会带该 attribute，属极端边缘；建议 fallback 时仍解析为模板或显式拒绝而非误判。
4. ⚠️ **孤绑定残留**：binding 1（`POST /api/users`）与 binding 46（`POST /api/system/authorizations/api-bindings`）无对应 controller 端点（实际为 `POST /api/users/create`、AuthorizationApiBindingController 无 POST 创建）。无害冗余，但说明 `data.sql` 与 controller 略有漂移，建议清理以保持映射单一真相。

## 五、结论

**admin 对外暴露的所有接口均已配置权限验证，不存在未授权（裸奔）接口。** 鉴权采用「默认拒绝 + 白名单放行」设计，绑定匹配为精确相等，机制正确且覆盖完整。第四节 4 项为优化建议，非阻断性安全问题。
