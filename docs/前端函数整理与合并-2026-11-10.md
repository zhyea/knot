# 前端函数整理与合并方案（2026-11-10）

> robin 指令：「整理并合并前端所有页面中的函数」。范围经确认 = `knot-front/src` 下
> `views/` + `components/` 共 140 个 `.vue`；动作 = 全量抽象同名套路函数；
> 交付 = 方案报告 + 代码改动 + 全量四道门禁。

## 1. 事实基线（脚本实测，非估计）

扫描脚本：提取每个 `.vue` 的 `<script setup>` 中 `function` 声明与带块体箭头函数，
对函数体做「去注释 + 字符串/数字占位 + 标识符按首次出现编号」的结构指纹，
再按「同名 + 同指纹 + ≥2 个文件」聚类。中间数据：
`audit/front-fn-scan-2026-11-10.json`、`audit/front-fn-dupes-2026-11-10.txt`。

| 指标 | 实测 |
|---|---|
| `.vue` 总数 | 140（`views` 33 / `components` 104 / 其他 3） |
| 函数定义总数 | **571** |
| 同名 + 同构簇 | **29 个**，涉及 **36 个文件** |
| 逐字相同（函数体全等，≥40 字符） | 15 个簇 |
| `views/` 中定义后全文件仅出现 1 次的疑似死函数 | 0 |
| 33 个页面引用公共 `composables/utils` | 32 个；`useListQuery` 被 22 页复用 |

**同名 ≠ 同构**（这是本次最关键的判定）：

| 函数名 | 定义数 | 不同骨架数 | 结论 |
|---|---|---|---|
| `submit` | 21 | **21** | 每个表单自己的必填校验/字段映射，无共同抽象层级 |
| `resetForm` | 18 | **18** | 每个表单自己的字段默认值 |
| `buildPayload` | 8 | **8** | 每个表单自己的请求体结构 |
| `handleAction` | 14 | 11（最大同构组 3） | 分派表各不相同 |
| `onClosed` | 12 | 7（最大同构组 6，均为 `form.id = null` 一行） | 复位内容各异 |

即：**把 `submit` / `resetForm` / `buildPayload` 按名字合并成一个通用 composable，
等于把 21/18/8 份不同业务塞进一个参数化函数**。这违反项目既定判据
（`MEMORY.md`「拆分判据是抽象层级不是行数」、`useStreamBuffer` 系列测试钉死的
「只抽状态、不抽编排」），判定为**不合并**，理由与证据写在本报告 §3。

## 2. 判定尺子

1. 抽象层级一致才抽；行数少不是拆分理由，反之逐字相同也不必然抽（纯转发壳不抽）。
2. 抽**状态机**与**纯计算**，不抽**业务编排**（不同 API / 文案 / 校验 / 分派表）。
3. 优先复用既有唯一出口，不新增第二套口径（`format.ts` 时间格式化、
   `useCopyToClipboard` 复制、`useEnumOptions.labelOf` 代码枚举、
   `useEnums.resolveEnumLabel` DB 枚举——两套枚举源禁止混用）。
4. 对外契约、固定字段集参数一律显式类型，不用 `Map` 拼装。
5. 空值占位唯一出口 `displayText` / `EMPTY_PLACEHOLDER`；状态 0 是合法值，禁 truthy。

## 3. 硬约束（改动前已核实）

| 约束 | 证据 | 影响 |
|---|---|---|
| 首屏加载不得进 composable | `src/views/listViewInitialLoad.test.ts:12-19,52-56` 源码级守门：凡含 `useListQuery(` 的视图必须有 `onMounted(` 或顶层无缩进调用语句 | 新 composable 内部**禁止** `onMounted(load)`；页面保留 `onMounted(load)` |
| 枚举下拉失败不得 reject | `src/composables/useEnums.test.ts:33-83` | 不新增任何枚举加载入口 |
| `labelOf` 不触发加载 | `src/composables/useEnumOptions.ts:98-111`：模块级 `labelOf` 只读 `enumMap`，`loadEnums()` 由 `useEnumOptions()` 触发 | 组件必须保留 `useEnumOptions()` 调用；删局部 label 函数前逐个确认加载链 |
| 「明确不拆」清单 | `useAuthorizationManagement`、`GatewayRequestHandler`、折扣簇、i18n、`RoutingRuleTestDrawer`、`ModelFormDrawer` | 不做组件结构拆分；如需动 `ModelFormDrawer`，仅允许「局部函数替换为公共 import」 |
| `useEnabledToggle` / `useEnums` / `useListQuery` 既有测试 | `useEnabledToggle.test.ts`、`useEnums.test.ts` | 扩展只能加可选参数，不得改既有 0 值 / 回滚 / 幂等短路语义 |
| UI 显示格式变更需 robin 确认 | `USER.md` | `DepartmentListPanel` / `UserListPanel` 的 `toLocaleString("zh-CN")` 时间格式**本批不动** |
| 行尾 | `.vue` 为 CRLF，`.ts` 多为 LF | 改动按行处理并逐文件复核 `d.count('\r') - d.count('\r\n') == 0` |

### 4.2 不抽（附判据）

| 函数族 | 判据 |
|---|---|
| `submit` / `resetForm` / `buildPayload` | 21/18/8 个定义对应 21/18/8 种骨架；业务校验与字段映射属于各表单自身抽象层级 |
| `handleAction` / `remove` / `restore` / `onStatusChange` | 分派表、API、确认文案、失败回滚各异；属编排且与「只抽状态不抽编排」冲突 |
| `onClosed` | 7 种骨架；抽屉复位内容由各抽屉自己负责（`useStreamBuffer.ts:281` 已明确该职责归属） |
| `fieldError` ×3 / `onUpdate` ×2 / `loadModelOperationLogs` ×2 / `remove(index)` ×3 | 单行纯转发壳，抽出来只是多一层间接，净收益为负 |
| `modelTypeLabel`（`labelOf` 族）/ `modeLabel` / `planLabel` / `statusLabel`（`labelOf` 族） | 与 `useEnumOptions()` 的加载触发耦合；抽走会让枚举可能未加载，且各页 fallback 口径不同 |
| `DepartmentListPanel` / `UserListPanel` 的 `formatDateTime` | 用 `toLocaleString("zh-CN")`，与唯一出口格式不同 → 属 UI 变更，需单独确认 |
| `rowActions` ×3（`ModelListPanel` / `ModelPoolListPanel` / `ModerationWordManageView`） | 动作集与文案各不相同（复制 / 折扣策略 / 恢复排在前 / 日志叫「操作日志」）；做成工厂需要 6 个可选配置，抽象层级不成立。只合并逐字相同的两处 |
| `ModelDiscountDrawer` 的 `openCreate` / `openEdit` | 折扣簇在「明确不拆」清单内，且它自带 `onClosed` 复位链，不做结构改动 |
| `EnumManageView.openChangeLog(category)` | 参数是分类字符串而非 Row，无 id / name 概念，不属于同一状态机 |
| `DepartmentManageView` / `UserManageView` 的日志抽屉 | 变量名与语义是 `logDrawerTitle = "操作日志"`（固定标题），不取显示名，不属于 `useLogDrawer` 口径 |

### 4.3 明确不动的边界

- 不改 `useListQuery` 的首屏请求语义，不改 `useEnums.loadOptions` 的「永不 reject」。
- 不拆 `useAuthorizationManagement`、`ModelFormDrawer`、`RoutingRuleTestDrawer` 等组件结构。
- 不引入统一的 `useCrudForm` / `useSubmit`：`submit` 21 种骨架已证明无共同抽象。
- 不改 `usePageList` / `useAutoQuery` 的存量调用点（仅 2/1 处，属独立收口议题）。

## 7. 未决 / 风险

1. 「全量抽象」按实证口径执行 = 抽净 29 个同构簇中可抽的部分；`submit`（21 种骨架）、
   `resetForm`（18 种）、`buildPayload`（8 种）等**同名不同构**族不合并，理由见 §1 §4.2。
   若 robin 要求连这些也强制参数化，需另行确认（会改 60+ 表单文件，且违反「只抽状态不抽编排」）。
2. `ExternalModelListPanel` / `LogicalModelList` 的手写 `formatDateTime` 换成唯一出口后，
   空值占位由 `"-"` 变为 `"—"`（`EMPTY_PLACEHOLDER`），是红线修正但改变了显示字符。
3. `DepartmentListPanel` / `UserListPanel` 仍用 `toLocaleString("zh-CN")`（`2026/01/01` 风格），
   与全站唯一出口（`2026-01-01`）不同 —— 统一属 UI 变更，未做，等 robin 确认。
4. `useLogDrawer` 的显示名沿用原实现的 `||` 语义（空串 / 0 视为未填）；显示名字段不会是 0，
   但如未来复用该 composable 取数字字段，需重新评估。
5. 未 commit（未经 robin 批准）。`git status` 中 `docs/异步任务调研与通用轮询器方案-2026-10-27.md`
