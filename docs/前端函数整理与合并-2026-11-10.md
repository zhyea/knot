# 前端函数整理与合并方案（2026-11-10）

> robin 指令：「整理并合并前端所有页面中的函数」。范围经确认 = `knot-front/src` 下
> `views/` + `components/` 共 140 个 `.vue`；动作 = 全量抽象同名套路函数；
> 交付 = 方案报告 + 代码改动 + 全量四道门禁。

## 1. 事实基线（脚本实测，非估计）

扫描脚本：提取每个 `.vue` 的 `<script setup>` 中 `function` 声明与带块体箭头函数，
对函数体做「去注释 + 字符串/数字占位 + 标识符按首次出现编号」的结构指纹，
再按「同名 + 同指纹 + ≥2 个文件」聚类。中间数据：
`audit/front-fn-scan-2026-11-10.json`、`audit/front-fn-dupes-2026-11-10.txt`。

| 指标 | 实测 |
|---|---|
| `.vue` 总数 | 140（`views` 33 / `components` 104 / 其他 3） |
| 函数定义总数 | **571** |
| 同名 + 同构簇 | **29 个**，涉及 **36 个文件** |
| 逐字相同（函数体全等，≥40 字符） | 15 个簇 |
| `views/` 中定义后全文件仅出现 1 次的疑似死函数 | 0 |
| 33 个页面引用公共 `composables/utils` | 32 个；`useListQuery` 被 22 页复用 |

**同名 ≠ 同构**（这是本次最关键的判定）：

| 函数名 | 定义数 | 不同骨架数 | 结论 |
|---|---|---|---|
| `submit` | 21 | **21** | 每个表单自己的必填校验/字段映射，无共同抽象层级 |
| `resetForm` | 18 | **18** | 每个表单自己的字段默认值 |
| `buildPayload` | 8 | **8** | 每个表单自己的请求体结构 |
| `handleAction` | 14 | 11（最大同构组 3） | 分派表各不相同 |
| `onClosed` | 12 | 7（最大同构组 6，均为 `form.id = null` 一行） | 复位内容各异 |

即：**把 `submit` / `resetForm` / `buildPayload` 按名字合并成一个通用 composable，
等于把 21/18/8 份不同业务塞进一个参数化函数**。这违反项目既定判据
（`MEMORY.md`「拆分判据是抽象层级不是行数」、`useStreamBuffer` 系列测试钉死的
「只抽状态、不抽编排」），判定为**不合并**，理由与证据写在本报告 §3。

## 2. 判定尺子

1. 抽象层级一致才抽；行数少不是拆分理由，反之逐字相同也不必然抽（纯转发壳不抽）。
2. 抽**状态机**与**纯计算**，不抽**业务编排**（不同 API / 文案 / 校验 / 分派表）。
3. 优先复用既有唯一出口，不新增第二套口径（`format.ts` 时间格式化、
   `useCopyToClipboard` 复制、`useEnumOptions.labelOf` 代码枚举、
   `useEnums.resolveEnumLabel` DB 枚举——两套枚举源禁止混用）。
4. 对外契约、固定字段集参数一律显式类型，不用 `Map` 拼装。
5. 空值占位唯一出口 `displayText` / `EMPTY_PLACEHOLDER`；状态 0 是合法值，禁 truthy。

### 8.2 补合并：枚举 label 一行转发函数

第一阶段 §4.2 把 `modelTypeLabel` / `modeLabel` / `planLabel` / `statusLabel` 判为不抽，
理由是「抽走会丢掉 `useEnumOptions()` 的加载触发」。续批把判据拆开：
**不能抽的是「纯函数」，不是「展示层抽象」** —— 只要抽象是 composable、内部照常调用
`useEnumOptions()`，加载链就不断；fallback 口径差异用参数化而不是复制解决。

新增 `src/composables/useEnumText.ts`：

- `useEnumText(enumName, {fallback, emptyText})` → `(code: unknown) => string`，
  内部 `const {labelOf} = useEnumOptions();`，空值短路严格判 null / undefined / `""`（0 是合法 code）。
- `useModelTypeText()` → `useEnumText("ModelTypeEnum", {emptyText: EMPTY_PLACEHOLDER, fallback: String})`。
- 不碰 `useEnums`（DB 枚举），两套来源继续隔离。

覆盖 **13 个枚举 label 函数 → 13 个工厂调用**（9 个 `.vue`）：
`modeLabel` ×4、`planLabel` ×3、`statusLabel` ×1、`modelTypeLabel` ×3、
`billingModeLabel` ×1、`pricingPlanLabel` ×1。
`PricingPreviewDrawer` 模板仍直接用 `enumLabelOf("PricingPhase", ...)`，故保留该文件的
`useEnumOptions()`；其余文件删掉不再使用的 `useEnumOptions` import（`--noUnusedLocals` 才暴露）。

另：`useEnabledToggle.onChanged` 放宽为 `() => void | Promise<unknown>`，包装层

### 11.4 ④ 统一启用态 4 种口径：按数据形态分组，不一刀切

全仓扫出 34 个判断点，先按「是不是同一数据形态」分组，而不是按「长得像不像」：

| 形态 | 例子 | 处置 |
|---|---|---|
| 列表行 primitive boolean | 9 处 `:model-value="row.enabled !== false"`、3 处表单回填、2 处 prev | **收口**到 `isRowEnabled` |
| el-switch change 入参（boolean/number/string） | `useEnabledToggle` + `RoutingRuleListPanel` + `TestRequestPresetView` 各抄一份逐字相同的 `enabled !== false && enabled !== 0 && enabled !== "false"` | **收口**到 `normalizeEnabledFlag` |
| 配置 JSON `Boolean enabled`（可空） | retryPolicy `!== false`（默认**开**）、ejectionPolicy / stickyPolicy `=== true`（默认**关**） | **不统一**：差异是业务默认值，统一会静默改策略行为 |
| 数字状态列 `status` | `TestRequestPresetFormDrawer` 的 `row?.status === 0`、View 里的 `prevStatus === EnabledStatus.ENABLED` | **不统一**：0 是合法停用值，不能与 boolean 混在一个函数 |
