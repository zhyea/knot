## 2. 统一状态语义

### 2.1 status 与 is_deleted 的边界

| 维度 | 负责什么 | 允许进 status | 落地形式 |
|---|---|---|---|
| 可用性 | 对象是否允许被业务使用 | 是 | `EnabledStatusEnum` 1/0 |
| 生效性 | 配置是否当前生效 | 是（当前都是二态） | 复用 `EnabledStatusEnum` 1/0，页面文案按字段显示「生效/停用」 |
| 流程阶段 | 对象处于哪个工作流节点 | 是 | 领域独立枚举 |
| 删除性 | 记录是否被逻辑删除 | **否** | `is_deleted` TINYINT |
| HTTP 状态码 | 网络协议响应码 | 不在范围 | 保持数字，不动 |
| SSE 事件名 | 传输事件类型 | 不在范围 | 保持字符串；事件 payload 内的业务状态必须数字 |

**一列一维度**：`kb_billing_rules` 改造后 `status=0` 表示停用、`is_deleted=1` 表示删除，删除记录不再用 `status` 表达。列表默认 `is_deleted = 0`，看回收站显式传 `includeDeleted = true`。

### 2.2 数字 code 规则（冻结，实施时不得偏离）

1. **二态**：`ENABLED = 1`、`DISABLED = 0`。历史 `ACTIVE/INACTIVE` 仅作为迁移输入映射，不作为持久化 code。
2. **`0` 是合法值**。所有前后端代码禁止 `if (status)` / `status || default` / `status ?? ENABLED` 这类把 0 当缺省的写法；空值判断只能用 `status === null || status === undefined`。
3. **多态**：正整数从 1 递增，**code 写死在枚举构造器里**，禁止 `ordinal()`、禁止按声明顺序推导。已发布 code 不复用；废弃值保留解析能力并标 `@Deprecated`。
4. **DB 类型**：二态 `TINYINT`；多态 `TINYINT`（当前最大 code 5，足够）。全部 `NOT NULL` + 数字默认值 + code 含义 COMMENT。
5. **Java**：枚举显式持 `int code`，提供 `fromCode(Integer)` / `requireCode(Integer, String)` / `codes()`。Service 内禁止裸数字字面量与字符串拼接。
6. **REST**：请求、响应、查询条件中的业务状态一律 JSON number。不做兼容窗口——同仓同版本，前后端一起发。
7. **非状态枚举不动**：模型类型、协议、计费单位、币种、模型族等继续用字符串 code。
8. **`is_deleted` 类型**：`TINYINT`，Java 侧 `Integer isDeleted`（与既有 `ModelEntity.java:32` / `ModelPoolEntity.java:18` 一致，**不用 boolean**，避免第二份真相），对外 DTO 沿用现有 `isDeleted` 字段。

### 3.4 registry 契约变更

```
现状：GET /api/common/enums
     -> { "EnabledStatusEnum": { "1": "启用", "0": "禁用" }, "ModelTypeEnum": { "CHAT": "对话" } }

目标：GET /api/common/enums
```

## 5. 后端实施清单

### 5.1 knot-common：枚举与契约

1. **新建** §3.1 的 8 个枚举 + **`EnabledStatusEnum`**。
2. **`EnumOption` 的泛型化难题与解法**（前一版方案未提及，是真实阻力）：
   - 现状：`EnumOption.java:12` `String code();`，全仓 **18 个枚举** `implements EnumOption`。
   - 直接改成 `EnumOption<C>` 会打断全部 18 个，且 `EnumOptionRegistry.java:73` 的 `put(..., EnumOption[] values)` 在泛型后无法构造 `EnumOption<?>[]`（Java 泛型数组无 unchecked 之外的路）。
   - **采用解法**：`EnumOption` 保持不变（`String code()`），新增 `NumericEnumOption`（`int code()`）。registry 改用 `List<?>` 形参 + 两个 `put` 重载：
     ```java
     private static <E extends Enum<E>> void put(Map<String, List<EnumOptionItem>> target,
                                                 String key, E[] values, Function<E, EnumOptionItem> mapper)
     ```
     数组传 `ModelTypeEnum.values()`（`E[]`）不再是 `EnumOption[]`，泛型数组问题消失。
   - `EnumOptionItem` 为 record：`record EnumOptionItem(int code, String label)` 与 `record EnumOptionItem(String code, String label)` 二选一 → **改用单一 record + `Object code` 字段不可取**（序列化不可控）。**结论：registry 输出 `List<Map<String,Object>>` 由 Jackson 直接序列化各枚举的 code/label，或定义 `EnumOptionItem(Object code, String label)` 并在测试中断言 `code` 的 JSON token 类型**。实施时以测试断言为准，不靠 `Object` 反射猜。

### 7.4 `kb_billing_rules` 迁移片段

```sql
-- ① 加列
ALTER TABLE kb_billing_rules
  ADD COLUMN is_deleted TINYINT(1) NOT NULL DEFAULT 0 COMMENT '逻辑删除：0-否 1-是';

-- ② DELETED 回填（先做，避免后续 CASE 把它归成 NULL）

UPDATE kb_billing_rules SET status = 'DISABLED'  WHERE status = 'INACTIVE';

ALTER TABLE kb_billing_rules
  MODIFY status TINYINT NOT NULL DEFAULT 0
```

### 7.5 回滚

1. 停写。
2. 反向映射：`UPDATE t SET status='ENABLED' WHERE status=1; UPDATE t SET status='DISABLED' WHERE status=0;`（各域按 §4 矩阵的 code 表反查）。

### 7.6 收尾：重新整理 `schema.sql` 与 `data.sql`（独立验收项）

> robin 2026-10-08 追加要求。迁移脚本只负责**把既有库改到位**；`schema.sql` / `data.sql`
