# 修复记录：登录成功后立刻被踢回登录页

- 日期：2026-09-22
- 现象：登录返回 `success:true`（token 正常），紧接着前端自动请求
  `GET /api/me/authorizations` 得到 `{success:false, code:10000, message:"当前用户无权访问该接口: GET /api/me/authorizations"}`，
  随后自动调用 `POST /api/auth/logout`，用户被弹回登录页并提示「登录已过期」。
- 性质：接口级权限数据缺失 + 授权失败错误码语义错位（非 token / 登录逻辑问题）。

## 一、根因链路

| # | 位置 | 说明 |
|---|------|------|
| 1 | `knot-front/src/composables/useAuth.js:116` | 登录成功后立即 `loadAuthorizations()`；`:84` 发起 `GET /api/me/authorizations` |
| 2 | `knot-admin/.../controller/CurrentUserController.java:30` | 该接口标了 `@AuthCheck`，进入 `AdminAuthorizationInterceptor` 的接口级鉴权 |
| 3 | `knot-admin/src/main/resources/db/data.sql:143` | 绑定 `(16, 18, 'GET', '/api/me/authorizations')` → 需要权限 `system:settings:view`（id=18） |
| 4 | `knot-service/.../AdminAuthorizationService.java:46-47` | admin 当前不持有该权限 → 抛 `UnauthorizedException` |
| 5 | `knot-admin/.../GlobalExceptionHandler.java:36` | 映射为 **HTTP 401 + code 10000** |
| 6 | `knot-front/src/api/http.js:47-53` | 把「非登录请求的 401」一律当登录过期 → `logout()` + 跳 `/login` |

补充：`MainLayout.vue:242-243` 每次挂载（= 每次刷新页面）都会调用同一接口，因此刷新页面同样被踢。

## 二、为什么 admin 会缺权限（种子数据缺陷）

- 「ADMIN 拥有全部权限」原实现是**一次性快照**：
  `INSERT IGNORE INTO ks_role_permissions SELECT 1, id FROM ks_permissions;`（位于 data.sql 中段）
  —— 只授予**执行那一刻已存在**的权限。
- 权限 18（`system:settings:view`）与 19–26（model / routing / billing 的 PAGE 权限）都在该快照之后才插入，
  而这两处的角色补授只写了 role 2/3，**漏了 role 1**。
- 实测库内 `admin`（user 1 → role 1）只有 **48 / 57**，缺 `{18, 19, 20, 21, 22, 23, 24, 25, 26}`；
  与「快照覆盖的 45 条 + 55 + 56 + 57 = 48」完全吻合。
- 后果：**任何全新初始化的库（首次部署 / 重建库 / CI）都会踩到**，而非仅本机偶发。

## 三、落地内容

| 项 | 文件 | 改动 |
|---|------|------|
| 1 种子修复 | `knot-server/knot-admin/src/main/resources/db/data.sql` | 删除中段的一次性快照；在**文件末尾**新增权威授权块：`INSERT IGNORE ... SELECT r.id, p.id FROM ks_roles r CROSS JOIN ks_permissions p WHERE r.code='ADMIN'`，并加注释说明「新增权限无需再单独补授 ADMIN，本块永远留在文件末尾」；原位置留注释指向该块 |
| 2 存量库修复 | 本机 `knot` 库 | 执行同一条全量授予 SQL（`INSERT IGNORE`，补 9 行） |
| 3 解除自锁 | `knot-admin/.../config/WebMvcConfig.java` | 在 `adminAuthorizationInterceptor` 的 `excludePathPatterns` 增加 `/api/me/authorizations`——该接口只做认证，不做接口级授权 |
| 4 错误码语义 | `knot-common/.../error/ErrorCode.java`、新增 `ForbiddenException.java`、`knot-admin/.../GlobalExceptionHandler.java`、`knot-service/.../AdminAuthorizationService.java` | 新增 `FORBIDDEN("GW-SYSTEM-403")` 与 `ForbiddenException`；`GlobalExceptionHandler` 增加 `@ResponseStatus(FORBIDDEN)` 处理器；`AdminAuthorizationService` 中「当前用户无权访问该接口」与「接口未配置访问权限」改抛 `ForbiddenException` |

保持不变（有意）：
- `AuthInterceptor` 未登录 / token 无效仍返回 **401**（这是真正的「登录过期」）。
- `getAuthorizationInfo` 中「当前登录用户不存在或已删除」仍返回 **401**。
- 前端未改动：`http.js` 只在 401 时登出，403 走普通错误提示分支（`silentError` 可抑制），行为已符合预期。

## 五、遗留与建议

1. **`GET /api/health` 只接受 POST**：用 GET 探测会抛 `HttpRequestMethodNotSupportedException`，
   被 `GlobalExceptionHandler` 的兜底 `handleException` 记成 ERROR 并返回 500。属既有噪声（本次未改动），
   建议补一个 `HttpRequestMethodNotSupportedException` → 405 的处理器，或让 `/api/health` 支持 GET。
2. `data.sql` 中 `SELECT role_id, 55 FROM ks_role_permissions WHERE permission_id = 12` 一句
   在快照移除后对 role 1 已无实际效果（其 55 由文件末尾权威块保证），保留仅用于修补历史存量库，已加注释标注。
3. 后续新增权限 / 菜单时：写在 `data.sql` 对应位置即可，**不需要**再手工给 ADMIN 补授（末尾块会兜）。
