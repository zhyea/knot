# Knot 数据库表命名规范与重命名方案

> 编制日期：2026-09-21 ｜ 状态：**待评审，未执行**
> 权威 schema：`knot-server/knot-admin/src/main/resources/db/schema.sql`（52 张表）
> 配套产物：`docs/database/migration/`（映射 CSV、正向/回滚 SQL、代码替换脚本）

---

## 一、结论摘要

1. 确立 **4 个域前缀**：`ks_` 系统域（18）、`kb_` 业务域（31）、`kr_` 运行时流水域（1）、`kx_` 外部接入域（2），合计覆盖全部 52 张表。
2. 前缀语义与表名主体**不重复**：`sys_modules → ks_modules`、`external_model_sources → kx_model_sources`（去掉冗余 `sys_` / `external_`）。
3. 改造面实测：**35 个文件 / 545 处替换**（33 个 mapper XML + schema.sql + data.sql）。Java 侧无 SQL（无 `@Table`、无注解式 SQL），无需改动。
4. 风险集中在**执行顺序**：`spring.sql.init.mode=ALWAYS` 若先部署新包后迁移，会静默创建空表（详见第六节 R1）。

## 二、命名规范（新表一律适用）

| # | 规则 | 正例 | 反例 |
|---|---|---|---|
| R1 | 全小写 + 下划线，表名用**复数** | `kb_models` | `KB_Models`、`kb_model` |
| R2 | 必须带域前缀，前缀即域语义 | `ks_users` | `users` |
| R3 | 表名主体不再重复前缀已表达的语义 | `ks_modules`、`kx_model_sources` | `ks_sys_modules`、`kx_external_model_sources` |
| R4 | 关联表 = `<前缀>_<主实体>_<次实体>` | `kb_routing_rule_targets` | `kb_targets_of_rule` |
| R5 | 外键列保持 `<实体>_id`（不带前缀） | `provider_account_id` | `kb_provider_account_id` |
| R6 | 索引名 `uk_/idx_ + <新表名> + <列语义>`，长度 ≤64 | `uk_kb_models_code` | `uk_models_code` |

判定顺序（消除归属歧义）：**外部镜像 → kx｜自动流水 → kr｜平台自身 → ks｜其余 → kb**。

## 三、域划分与判据

| 前缀 | 域 | 归入判据 | 张数 | 典型表 |
|---|---|---|---|---|
| `ks_` | System 平台系统 | 平台自身运行所需，与对外业务无关：账号、组织、授权、菜单、审计、调度、字典、告警、缓存登记 | 18 | `ks_users` `ks_roles` `ks_permissions` `ks_alerts` |
| `kb_` | Business 业务配置 | 网关对外服务能力的核心配置，低频 CRUD、强一致：供应商/模型/应用/路由/计费/策略/插件/通知 | 31 | `kb_providers` `kb_models` `kb_logical_models` |
| `kr_` | Runtime 运行时流水 | 运行过程自动产生，只增不改，可按时间归档/清理 | 1 | `kr_plugin_execution_logs` |
| `kx_` | eXternal 外部接入 | 外部系统的数据镜像/快照，可重放重建，本地非权威源 | 2 | `kx_model_sources` `kx_model_items` |

### `kr_` 系列是否扩表 —— **不立项**（robin 拍板 2026-09-22）

曾建议新增 `kr_request_logs`（网关请求明细）/ `kr_usage_records`（用量流水）/ `kr_usage_daily`（日汇总），理由是 gateway 当前无调用明细落库、计费缺对账数据。**本次不做**，`kr_` 仅保留 `kr_plugin_execution_logs` 一张表；前缀体系仍为该方向预留了命名空间，后续若要建流水表直接归入 `kr_` 即可。

## 五、影响面（实测数据，非估算）

| 对象 | 数量 | 说明 |
|---|---|---|
| mapper XML | 33 个 | `knot-server/knot-dal/src/main/resources/mapper/*.xml` |
| schema.sql | 1 个 | `knot-admin/src/main/resources/db/schema.sql` |
| data.sql | 1 个 | `knot-admin/src/main/resources/db/data.sql`（740 行种子数据） |
| **替换总处数** | **545** | 全词匹配 `\b`，DRY RUN 实测（`DRY=1 bash docs/database/migration/apply-rename-in-code.sh`） |
| Java 文件 | 0（无需改） | 无 `@Table`、无注解式 SQL；命中的 `roles`/`users`/`models` 全是 JavaDoc 注释与 `@RequestMapping` 路径 |

前置安全前提（已核实）：
- `schema.sql` 中**无** `FOREIGN KEY` / `REFERENCES` / `CREATE VIEW` / `CREATE TRIGGER` → `RENAME TABLE` 无依赖阻塞。
- mapper 中**无** `${tableName}` 动态表名拼接 → 机械替换安全。
- 全词匹配下无包含关系误伤（`\bmodels\b` 不命中 `model_pools`，`\bproviders\b` 不命中 `provider_accounts`）。

## 六、风险与坑

| ID | 风险 | 位置 | 处置 |
|---|---|---|---|
| **R1** | **静默建空表**：`spring.sql.init.mode: ALWAYS` + `CREATE TABLE IF NOT EXISTS`，若先部署新包、后跑迁移，MySQL 会创建空的 `ks_*` 表、data.sql 再灌种子数据，应用照常启动但业务数据"消失" | `knot-admin/src/main/resources/application.yml:12-18` | **顺序强制：先迁移 → 后部署**；部署后立即跑校验 SQL（四段计数 + 旧表残留 + 行数抽样） |
| R2 | 迁移中断导致新旧名混杂 | 迁移脚本 | `RENAME TABLE` 单表原子；脚本按域分组、可重复执行（已改名表再执行会报错，需人工判断后跳过）；备回滚脚本 |
| R3 | `docs/database/schema.sql` 是**过期副本**（库名 `knot_ai_gateway`、缺 `departments`/`sys_*`、含已废弃 `plugins` 表） | `docs/database/schema.sql:2` | 本次一并删除或标注为"历史存档"，避免再次被误当权威源 |
| R4 | `knot-admin/target/classes/db/` 下有构建产物副本 | `knot-admin/target/classes/db/` | 属 `target/`，`mvn clean` 即可，无需手工处理 |
| R5 | 索引名未同步（98 个），其中 `idx_rrc_*`、`idx_task_runs_*`、`idx_module`、`idx_entity` 等不携带表名，无法机械映射 | `schema.sql` 各处 | **本次不改**（robin 拍板）：`RENAME TABLE` 不改索引名、也不产生冲突；索引名与表名不一致仅影响可读性，不改更安全 |
| R6 | 外部系统/BI/运维脚本直连旧表名 | 库外 | 迁移前 grep 一遍所有非仓库脚本；可选灰度视图（见下） |

### 灰度备选（如需零停机）

迁移后、代码切换前，可为旧名建可更新视图兜底：

```sql
CREATE OR REPLACE VIEW users AS SELECT * FROM ks_users;   -- 单表视图在 MySQL 中可 INSERT/UPDATE/DELETE
```

灰度期结束 `DROP VIEW users;`。**注意**：视图会让 R1 的"空表"问题更难被发现。**已拍板不采用**，整窗停服迁移（规模小、更可控）。
