# 计费规则模块技术方案

## 1. 架构设计
- 子模块：计费规则、实时计费、供应商账单对账。
- 组件：`BillingRuleEngine` 负责规则匹配与费率计算，`ReconciliationService` 负责供应商账单对账。

## 2. 数据设计
- 核心表：`kb_billing_rules`、`kb_billing_rule_versions`；基础价格和进阶方案配置统一保存在版本的 `config_json`，不再依赖 `billing_rule_version_items`。
- 复杂计费参数按方案既定结构写入 `config_json`；Token 阶梯使用根级 `ladder`，每项包含 `condition` 和完整 `unitPrices`，避免为不同供应商报价模型频繁扩表。

## 3. 计费模式与进阶定价方案

计费模式与进阶定价方案分层：计费模式决定按什么用量计费，进阶定价方案决定基础单价如何随条件变化。阶梯价格、高低峰价格不属于计费模式。

### 3.1 计费模式
- `TOKEN`：按输入 Token、输出 Token、缓存读取 Token、缓存写入 Token 分别计价，主流文本模型使用。
- `REQUEST`：按请求次数计价，适合轻量接口。
- `IMAGE`：按图片张数、分辨率、质量档位计价。
- `AUDIO`：按音频时长计价，默认按分钟。
- `VIDEO`：按视频生成时长计价，默认按秒。
- `EMBEDDING`：按输入 Token 计价，面向向量模型。
- `FREE`：免费额度或内部测试模型。
- `CUSTOM`：自定义计费模式，具体计算参数使用 JSON 配置保存，适合临时或非标准供应商计费规则。

### 3.2 进阶定价方案

- `FIXED`：使用基础价格，未配置进阶方案时的默认行为。
- `TIERED`：按累计用量选择价格档位，可叠加在 TOKEN、REQUEST、IMAGE、AUDIO、VIDEO、EMBEDDING 等模式上。
- `PEAK_OFF_PEAK`：按时区、星期、节假日和时间窗口选择高峰或低峰价格，可叠加在支持的基础模式上。

版本配置使用 `billingMode`、`pricingPlan`、`unit` 和 `configJson` 表达完整语义。计费链路先由 `billingMode` 提取标准用量，再由 `pricingPlan` 解析最终单价。详细模型与迁移规则见《计费规则优化方案：计费模式与进阶方案分层》。

实现备注：计费规则使用面向对象的领域模型维护。`config_json` 读取后应转换为具名的价格对象、条件对象和进阶方案对象，避免在服务层和计算器中使用 `Map<String, Object>`、`List<Map<...>>` 或字符串键分支。集合类只用于阶梯档位、时间窗口等天然的一对多数据，并统一使用明确元素类型和不可变集合。

## 4. 接口设计
- `GET/POST /api/billing/rules`
- `POST /api/billing/reconciliation`

## 5. 关键流程
- 实时计费：请求结束 -> 提取标准用量 -> 匹配计费规则 -> 按进阶定价方案解析单价并计算成本 -> 通过插件事件推送请求记录或成本明细。
- 对账流程：导入供应商账单 -> 按供应商账单维度匹配 -> 生成差异报告 -> 人工确认修正。

## 6. 异常与性能
- 成本聚合采用离线任务，避免影响主链路。
- 账单封账后禁止直接修改，只允许通过冲正记录修正。
