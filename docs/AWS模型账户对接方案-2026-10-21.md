## 1. 现状盘点（凭据字段体系已就位）

证据链（`文件:行`）：

- 凭据类型枚举 `ProviderCredentialTypeEnum`（knot-common）—— 现引用 `ProviderCredentialFields`，`requiredFields()` 返回**深拷贝 JsonNode 数组**（避免共享常量被改）；`requiredFieldNames()` 取 `required=true` 的 name，驱动保存校验。**AWS_AUTH 的 requiredFieldNames = `[accessKey, secretKey, region, endpointType]`**。
- 字段定义中心 `ProviderCredentialFields`（knot-common）—— 单字段常量（`ACCESS_KEY_FIELD` / `SECRET_KEY_FIELD` / `AWS_REGION_FIELD` / `ENDPOINT_TYPE_FIELD`）+ 类型字段集合（`AWS_AUTH_FIELDS`）。`accessKey`/`secretKey` 由 AWS_AUTH 与 AK_SK **共用同一份定义**（标签口径不可漂移，单测 `sharedFieldDefinitionsStayIdenticalAcrossTypes` 守卫）。`AWS_REGION_FIELD` 是 select，14 个区域含 `cn-north-1`/`cn-northwest-1`（中国区）；`ENDPOINT_TYPE_FIELD` 是 select，选项 `bedrock-runtime`/`bedrock-mantle`，默认 `bedrock-runtime`。
- 校验：`ProviderService.validateCredential`（`ProviderService.java:286`）：`fromCode` 解析类型，`requiredFieldNames()` 逐个非空校验 → 缺字段抛 `VALIDATION_ERROR`。**前端零硬编码字段名映射表**：`ProviderAccountFormDrawer` 用 `normalizeCredentialFields` 按 `type` 渲染（text/password/textarea/select），`credentialInputType` 决定控件。
- 选项下发：`ProviderController` → `authApplierCatalog.definitions()`（`ProviderService.java:138`）、`ModelController` → adapter/extractor definitions（`ModelService.java:183/199`）—— **新增策略自动出现在下拉**。
- 鉴权策略族 `UpstreamAuthApplier`（`apply` 只碰头）；请求适配器族 `UpstreamRequestAdapter`；用量提取器族 `UsageExtractor`；协议执行器 `AbstractUpstreamProtocolExecutor`（WebClient，阻塞到响应头就绪）。
- `UpstreamRequestContext`（protocol/requestBody/model/provider/authConfig/binding/authApplier），`UpstreamProxyClient` 组装 `authConfig = credentialSupport.toAuthConfig(credential)`（AES-GCM 密文解密后 JSON）。

**顺带发现（存量缺陷，不在本方案范围）**：`data.sql` qwen-image 两个 binding 的 `request_adapter='QWEN'` 代码里不存在（全仓 grep 无 `QwenRequestAdapter`），运行期被 `UpstreamRequestAdapterRegistry` 静默兜底成 `PASSTHROUGH`。建议另开单修。

## 2. Bedrock 与现有供应商的技术差异（v2 更新）

| 维度 | OpenAI / Anthropic 直连 | AWS Bedrock |
|---|---|---|
| 端点 | 固定 base_url + 固定 path | **runtime**：`bedrock-runtime.<region>.<partition域>/model/<modelId>/converse`（Converse）；**mantle**：`bedrock-mantle.<region>.api.aws/v1/chat/completions`（OpenAI 兼容，无 Converse）。endpointType 决定 host 前缀与 SigV4 service，region 决定 partition 域 |
| 鉴权 | 静态头（Bearer / x-api-key） | **SigV4**（HMAC 签名，时间窗 5min）+ `endpointType` 决定 SigV4 service：**runtime→`bedrock`，mantle→`bedrock-mantle`（已核实，非同 service）** |
| 请求体 | OpenAI / Anthropic 原生格式 | **Converse** 统一格式 |
| 响应体 | 原生格式 | `output.message.content[]` + `stopReason` + `usage{camelCase}` |
| 流式 | SSE 文本 | **AWS EventStream 二进制帧**（不是 SSE），usage 在 metadata 事件 |
| 错误 | status + JSON | status + `x-amzn-ErrorType` |
| 用量口径 | snake_case | camelCase `inputTokens/outputTokens/totalTokens/cacheReadInputTokens/cacheWriteInputTokens` |

## 3. 总体设计

关键路径：

1. 客户端 CHAT_COMPLETIONS → 路由选中 Bedrock 模型（`kb_models.upstream_model = anthropic.claude-...-v1:0`）。
2. `UpstreamProxyClient` 组装 context（`binding.requestAdapter = BEDROCK_CONVERSE`，`credential.authApplier = AWS_SIGV4`，`authConfig` 含 ak/sk/region/endpointType）。
3. `TextGenerationProtocolExecutor` → `BedrockConverseRequestAdapter`：`resolveBaseUrl`（region+endpointType→host，或 model.base_url 覆盖）+ `buildRequestBody`（chat→converse）+ `resolvePath`（`/model/{upstream_model}/converse`）。
4. **改造点**：executor 先把 body 序列化为 `byte[]`（SHA-256 得 payloadHash），`resolveBaseUrl` 定 host，调签名钩子 → `AwsSigV4AuthApplier` 读 region/endpointType 算 service，产出 `Authorization` + `X-Amz-Date`（+ `X-Amz-Security-Token`）。
5. WebClient 发出（**与 hash 同字节**）→ Bedrock。
6. 响应 → `adapter.handleResponse`（converse→OpenAI）→ `BedrockConverseUsageExtractor`（camelCase→TokenBillingUsage）→ 计费/频控照旧。

## 5. 详细设计

### 5.1 凭据与签名

凭据（`kb_provider_credentials.encrypted_config`，AES-GCM 密文，解密后 JSON）：

```json
{"accessKey":"AKIA...","secretKey":"...","region":"us-east-1","endpointType":"bedrock-runtime"}
```

`AwsSigV4AuthApplier`（code=`AWS_SIGV4`，credentialTypes=`{AWS_AUTH}`）：

- `sign(UpstreamSignableRequest req, HttpHeaders headers, ctx)`：
  - region = `AuthConfigSupport.value(authConfig, "region")`；endpointType = `value(authConfig, "endpointType")`（缺省 `bedrock-runtime`）。
  - service = `AwsBedrockEndpointResolver.serviceName(endpointType)`（`bedrock-runtime`→`bedrock`，`bedrock-mantle`→`bedrock-mantle`，**官方核实**）。
  - `X-Amz-Date: <yyyyMMdd'T'HHmmss'Z'>`（**UTC**，每次实时取，不可缓存）。
  - sessionToken 非空 → `X-Amz-Security-Token`（v1 一般无，按字段系统日后可加）。
  - canonical request（method/uri/host/headers/payloadHash）→ string to sign（scope = `<date>/<region>/<service>/aws4_request`）→ signing key（HMAC 链）→ `Authorization: AWS4-HMAC-SHA256 Credential=.../..., SignedHeaders=host;x-amz-date, Signature=...`。
  - 时钟源：`Instant.now()`，**必须 UTC**（踩坑：`LocalDateTime.now()` 带本地时区）。
  - host 取自 `req.url()`（已由 `resolveBaseUrl` 定好），保证签名 Host 头与实际发出一致。

`AwsSigV4Support`（纯静态函数族，无 Spring 依赖）：`canonicalRequest` / `stringToSign` / `signingKey` / `authorizationHeader`；SHA-256 + HMAC-SHA256（`javax.crypto`，**零新依赖**）。

`AwsBedrockEndpointResolver`（新增，纯函数，已按官方文档核实）：

- `serviceName(endpointType)`：查表 `bedrock-runtime→bedrock`、`bedrock-mantle→bedrock-mantle`（**官方确认 mantle service 名是 `bedrock-mantle`，非 bedrock**）；兜底取 `endpointType.split("-")[0]`。
- `runtimeDomain(region)`：`eusc-*`(EU 主权云)→`amazonaws.eu`、`cn-*`→`amazonaws.com.cn`、`us-gov-*`→`amazonaws-us-gov.com`、其余→`amazonaws.com`。
- `mantleDomain(region)`：`eusc-*`→`api.amazonwebservices.eu`、`cn-*`→`api.amazonwebservices.com.cn`、其余（全球+GovCloud）→`api.aws`。（**mantle 全球/GovCloud 用 `api.aws`，与 runtime 的 `amazonaws.com` 形态不同，且多一段**。）
- `host(endpointType, region)`：`bedrock-runtime`→`bedrock-runtime.{region}.{runtimeDomain}`；`bedrock-mantle`→`bedrock-mantle.{region}.{mantleDomain}`。
- `resolveBaseUrl(context)`：`model.baseUrl` 非空 → 原样返回（operator 覆盖，含 VPC/private/mantle 代理）；否则 `host(endpointType, region)`。未知 endpointType + 无 base_url → 抛 `BusinessException`（配置错误，防误配）。

executor 改造（`AbstractUpstreamProtocolExecutor`，最小侵入）：

- `execute()` 先算 `baseUrl = adapter.resolveBaseUrl(context)`（默认 `model.getBaseUrl()`）。
- `withBody()`：JSON 路径先把 body 用 ObjectMapper 序列化为 `byte[] payload`，算 `sha256Hex(payload)`，构造 `UpstreamSignableRequest(POST, joinUrl(baseUrl, path), payloadHash)` 交 `applier.sign(...)`；multipart 路径不签名（Bedrock 无 multipart）。
- 发出用 `BodyInserters.fromValue(payload)`——**字节级一致**（hash 什么发什么），签名验证第一雷区。
- `supportsStreaming` 增加 adapter 委托：`adapter.streamSupported(context)` 默认 true，Bedrock 适配器返回 false → 走整包 → 合成 SSE（D3a）。

`UpstreamSignableRequest` record（adapter.upstream 包）：`(String httpMethod, String url, String payloadHash)`——纯值类型，不引任何 HTTP 客户端类型。

### 5.2 请求适配器 BEDROCK_CONVERSE

| 钩子 | 行为 |
|---|---|
| `resolveBaseUrl` | `model.base_url` 非空→返回；否则 `AwsBedrockEndpointResolver.host(endpointType, region)`（endpointType/region 取自 authConfig） |
| `resolvePath` | `/model/{RFC3986(upstream_model)}/converse`（`upstream_model` 来自 `kb_models.upstream_model`，如 `anthropic.claude-sonnet-4-20250514-v1:0` 或推理配置 `us.anthropic.claude-...`） |
| `buildRequestBody`（入参 chat.completions 语义） | messages→converse messages：system 角色→`system[0].text`；user/assistant→`content[0].text`（P1 仅文本）；`max_tokens`/`max_completion_tokens`→`inferenceConfig.maxTokens`（缺失默认 1024）；`temperature`/`top_p`→inferenceConfig；`stop`→`stopSequences`；**丢弃** `n`/`stream`/`model`/`penalties`/`response_format`；`top_k` 等透传 `additionalModelRequestFields` |
| `handleResponse` | converse→OpenAI：`output.message.content[]` 文本块拼接为 `choices[0].message.content`；`stopReason` 映射（end_turn/stop_sequence→stop，max_tokens→length，tool_use→tool_calls，content_filtered/guardrail_intervened→content_filter）；补 `id`（`chatcmpl-<uuid>`）、`created`、`object`、`model=<upstream_model>` |
| `extractUsageFromBody` | usage camelCase → TokenBillingUsage；`cacheReadInputTokens`→cacheReadTokens、`cacheWriteInputTokens`→cacheWriteTokens；缓存加回输入总量（Converse 的 inputTokens **不含**缓存读写——待实测，见 R2） |
| `streamSupported` | false（P1） |
| `protocol()` | `{CHAT_COMPLETIONS, MESSAGES, RESPONSES, COMPLETIONS}` |

> **mantle 复用说明**：`bedrock-mantle` 不支持 Converse/InvokeModel，仅暴露 OpenAI 兼容（Chat Completions `/v1/chat/completions` 或 `/openai/v1`、Responses）+ Anthropic Messages。因此 **mantle 模型直接绑定既有 `OPENAI_COMPATIBLE` 适配器（resolvePath `/v1/chat/completions`）+ `DEFAULT-TOKEN` 用量提取器（snake_case usage）**，零新适配器代码；`BEDROCK_CONVERSE` 仅用于 `bedrock-runtime` 的 Converse 路径。`AwsBedrockEndpointResolver` 同时服务两类端点（host/domain/service 形态不同），`AWS_SIGV4` 鉴权按 `endpointType` 取 service（`bedrock` / `bedrock-mantle`）。部分 mantle 模型路由前缀为 `/openai/v1`（非 `/v1`），此类用 `model.base_url` 覆盖；P1 默认 `/v1`。

### 5.3 用量提取器 BEDROCK_CONVERSE

`TokenBillingUsage.from()` 只认 snake_case → 专用提取器：`usage.inputTokens/outputTokens/totalTokens/cacheReadInputTokens/cacheWriteInputTokens` → TokenBillingUsage；`billingModes={TOKEN}`、`calculator=TokenBillingModeCalculator`（照 AnthropicUsageExtractor 模板）。Anthropic-on-Bedrock 若走 InvokeModel 绑定：响应是 Anthropic 原生格式 → 直接用 `ANTHROPIC` 提取器，**零新码**。

### 5.4 错误映射（D8）

| Bedrock 错误 | HTTP | 网关处理 |
|---|---|---|
| ThrottlingException | 429 | 现有 UPSTREAM_ERROR + retry/failover 主干照旧（Retry-After 解析已有） |
| AccessDeniedException | 403 | UPSTREAM_ERROR；**不可重试**（签名/权限问题无意义）——需确认 failover 判定是否只看 5xx/429 |
| ValidationException | 400 | UPSTREAM_ERROR；适配器保证必填后应极少见 |
| ResourceNotFoundException | 404 | UPSTREAM_ERROR（modelId 写错） |
| ModelErrorException / InternalServerException | 4xx/5xx | UPSTREAM_ERROR + failover |
| ServiceQuotaExceededException | 429/402 | 同 Throttling |

executor 的 `upstreamFailure` 已带齐 status+body+requestId，错误体 message 仅进排障日志（`x-amzn-ErrorType` 头解析为可选增强）。

- 凭据字段（accessKey/secretKey/region/endpointType）按 type 自动渲染：**region/endpointType 是 select 下拉**（含中国区、默认值预填），**secretKey 是 password**。
- **零前端代码改动**（v1 不纳入 sessionToken）。

### 5.7 端点解析（v2 新增，对应 D4/D12）

`AwsBedrockEndpointResolver` 是 host/service 推导的单一来源，规则：

| 输入 | 输出 |
|---|---|
| model.base_url 非空 | 直接用作 host（VPC/private/mantle 代理场景；SigV4 service 仍由 endpointType 定） |
| endpointType=`bedrock-runtime`, region=`us-east-1` | host=`bedrock-runtime.us-east-1.amazonaws.com`，service=`bedrock`（Converse/InvokeModel 原生路径） |
| endpointType=`bedrock-runtime`, region=`cn-north-1` | host=`bedrock-runtime.cn-north-1.amazonaws.com.cn`，service=`bedrock`（中国区后缀） |
| endpointType=`bedrock-runtime`, region=`eusc-de-east-1` | host=`bedrock-runtime.eusc-de-east-1.amazonaws.eu`，service=`bedrock`（EU 主权云后缀） |
| endpointType=`bedrock-mantle`, region=`us-east-1` | host=`bedrock-mantle.us-east-1.api.aws`，service=`bedrock-mantle`（**全球/GovCloud 用 `api.aws`，非 `amazonaws.com`**；OpenAI 兼容 `/v1`） |
| endpointType=`bedrock-mantle`, region=`eusc-de-east-1` | host=`bedrock-mantle.eusc-de-east-1.api.amazonwebservices.eu`，service=`bedrock-mantle`（EU 主权云） |
| 未知 endpointType 且 base_url 空白 | 抛配置错误，阻断启动/调用（防误配） |

## 8. 风险与未验证项

- **R1** 签名时间窗：网关时钟漂移 >5min → 全量 403。建议 P1 加启动自检（仅文档告警，或对 bedrock 发一次 `ListFoundationModels`）。标注未验证。
- **R2** Converse 的 `inputTokens` 是否含缓存读写——影响计费口径，**待真实环境实测**（P1 假上游无法回答）。
- **R3** 本机无 AWS 账号/凭证：全部链路验证走假上游 + botocore 离线对拍；**未经真实 AWS 环境验证**，上线前须真实 AK/SK 跑一次连通性冒烟。
- **R4** Cohere embedding 无 usage 回传 → 计费 0 或估算，口径待运营拍板（D7）。
- **R5** P1 流式降级为单 chunk SSE：长响应 TTFT 体验差，P2 必须补流式。
- **R6** Bedrock 区域可用性：模型×region 矩阵由运营维护，`upstream_model` 填错 → ResourceNotFoundException 404。
- **R7（已核实）** `bedrock-mantle` SigV4 service 名与 host 形态已**官方核实**：service=`bedrock-mantle`（非 bedrock；OpenAI Java SDK / 官方 curl / AWS 文档 / IAM action 一致确认）；host=`bedrock-mantle.{region}.api.aws`（全球/GovCloud）/ `api.amazonwebservices.eu`（EU 主权云），**不是** `bedrock-mantle.{region}.amazonaws.com`。mantle 不支持 Converse，仅 OpenAI 兼容 → 复用既有 `OPENAI_COMPATIBLE` 适配器，P1 即覆盖 mantle（transport+SigV4+复用），无需 P3。
- **R8（新增）** 中国区 `cn-*`：host 后缀 `amazonaws.com.cn` 已处理，但中国区 SigV4 仍需 `cn-north-1` 作为 signing region（已满足）；**中国区账号的 IAM/AccessDenied 排障**未经实测。
