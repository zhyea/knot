# 前端 props 类型收敛复盘（unknown[] 类型错误分析）

> 复盘日期：2026-10-06 ｜ 涉及：`knot-front` ｜ 结论：**报告的"17 个阻断构建错误"在当前代码下不存在，但报告点出的裸 `type: Array` 现象真实，已作为卫生项全部收敛。**

## 一、问题来源

2026-10-05 收到一份前端类型检查分析报告，声称 `npm run type-check` 产出 **17 个错误**：

- 16 个 `unknown[]` 透传 `el-table` 的 `:data` 时 → `DefaultRow[]` / `Dict[]` 的 `TS2322`；
- 1 个 `src/layouts/MainLayout.vue(39)` 的 `routePath` 可选值错误。

报告据此判定这些错误会**阻断生产构建**（`build` 先跑 `vue-tsc --noEmit`），并列出 16 个待修组件。

## 二、实测现状（证据优先，不是印象）

| 复验步骤 | 做法 | 结果 |
|---|---|---|
| 门禁实测 | `npm run type-check` | **exit 0、零错误** |
| 排除"门禁没真跑" | 在 `EnumCategoryListPanel.vue` 注入 `const __probe: number = "must-fail"` | 报 `TS2322`、**exit 2** |
| 复现报告场景 | 临时组件用报告指认的最坏写法：裸 `Array` + `default: unknown[]` + `<el-table :data>`（含全局组件与 `import { ElTable }` 局部两种） | **exit 0** |
| 复现第 17 条 | `<el-menu-item :index="string \| undefined">` | 同样不报错 |

> 探针已还原、临时文件已删，工作区未残留。

## 三、根因：报告错在哪里

**3.1 报告说对的部分**

- `type: Array` 在 `vue-tsc` 下确实把 prop 推导为 `unknown[]`；`default` 的返回类型不会反向修正 prop。
- 16 个组件确实存在裸 `type: Array`（文件名、行号 grep 全部对得上），`EnumCategoryListPanel.vue:39` 甚至直接是 `unknown[]`。

**3.2 报告推错的部分（关键）**

- 项目实际装的是 **element-plus 2.13.7**（`package.json` 写 `^2.9.11`）。其 `TableProps<T extends DefaultRow = any>`（`es/components/table/src/table/defaults.d.ts:11,88`）在模板里实例化时泛型 `T` 落默认 `any` → `data?: any[]`。**`unknown[]` 可以赋给 `any[]`**，根本不触发 `TS2322`。
- 报告假定的硬约束 `DefaultRow[]`（`DefaultRow = Record<PropertyKey, any>`）在当前版本**不存在**。
- `MainLayout.vue` 的 `el-menu-item` 的 `index?: string` 是**可选** prop，`string | undefined` 合法，同样不报错。

**3.3 结论**

报告的现象描述可信，但"→ 产生 TS2322 → 阻断构建"是**基于旧版本/旧配置或纯推断**的因果，在当前 `element-plus 2.13.7 + vue-tsc 3.3.11 + strict` 环境下不可复现。环境：`typescript 5.9.3`、`tsconfig` `strict: true`。

## 四、我们做了什么

把 19 处 props 数组声明统一收敛为规范写法（**纯静态类型卫生，不是故障修复**）：

- 16 个列表 panel 的 `rows` / `users` / `summaries` → `Array as PropType<Row[]>`；
- `EnumSelect.vue:41 includeCodes` → `PropType<string[] | null>`（报告漏列）；
- `TierPriceFields.vue:34` 旧式 `Array as () => TierIssue[]` → `PropType<TierIssue[]>`；
- `EnumSelect.vue:29 modelValue` 的 `[String, Number, Array]` → `PropType<string | number | (string | number)[]>`（v-model 双向，5 个调用点实测不报错）。

11 个文件补了 `import type {PropType} from "vue"`。门禁：`type-check` **exit 0**、`build` **exit 0**。

## 五、后续开发提示 ★

1. **外部 / AI 分析报告先实测复验再行动。** 特别是"报 0"的结论，用**探针法**证伪：注入一条必然报错的语句（如 `const p: number = "x"`），确认检查链路真的在跑；探针报错 = 链路正常、0 是真绿，探针不报 = 门禁根本没跑。不要直接采信"有 N 个错误"的结论。
2. **props 数组一律写 `Array as PropType<T[]>`**，不要裸 `type: Array`、也不要旧式 `Array as () => T[]`。通用行类型 `Row = Dict`（`src/types/index.ts`）。
3. **真实门禁 = `npm run type-check` + `npm run build`**，两者都要过。`build` 前先物理删除 `dist`（`.NET [System.IO.Directory]::Delete(dist, $true)`），否则 vite 清空 dist 会被沙箱 safe-delete 钩子拦，报 `✗ Build failed` + `EXIT=1`——**不是代码问题**。
4. **build 后必须 `git checkout -- knot-front/components.d.ts`（只还原这一个文件，禁用通配符）。** `unplugin-vue-components` 在 build/dev 时改写它；残留的残缺/差异版本会导致 `TS7006` 假错。
5. **多会话并行写码时，改动范围严格自分。** 本次并行存在另一会话的 routing-rule retry-policy 改动，互不触碰；还原生成文件、查 diff 都只用精确路径，避免回滚他人半成品。
6. **element-plus 升级预警：** 若某天该库把 `TableProps` 默认泛型收紧为 `DefaultRow`（非 `any`），今天收敛的 19 处会**一次性集体报 `TS2322`**。届时这是预期内的版本迁移，不是回归，按 `PropType` 已是正确写法直接放行即可。
