## 六、清理建议（按优先级）

### P1 — 建议尽快收敛（安全相关）

1. **A1 凭据三格式**：`decrypt()` 的明文透传意味着库里任何未加密串都会被当密钥使用。建议：① 先跑一遍全库扫描（`kb_provider_credentials` 等凭据表，无 `ENC:` 前缀的行清单）；② 一次性重加密迁移（加密功能上线时漏网的存量行）；③ 迁移完成后删 v1 解密路径与明文透传，`decrypt()` 对非密文直接抛错。**这是全库唯一「静默接受不安全输入」的兼容路径。**

### P2 — 过渡期容忍，可维持现状（受控）

2. **A3 `fromCodeOrDefault`**：网关热路径的宽松读有 `requireCode` 写入口把守，且注释明确分工，保留。
3. **A2/A6/A7 状态与高低峰数字化**：前端已全量数字 code，剩余容忍是防旧书签/旧配置。建议同批做一次「确认无存量后删除」的检查（查询参数走 `EnabledStatusEnum.parse` 的只有 ModelPoolService/ModelService 两处 list 接口，前端调用方已数字），删不掉就维持。
4. **B1 `resolveTargetCode` 的 targetId 反查**：建议 grep 前端确认无调用方传 `targetId` 后下线该分支，DTO 同步删 `targetId` 字段（符合「不留兼容兜底」）。

### P3 — 观察 / 决策项

5. **B3 HealthStatusEnum**：上线前拍板「是否真需要兼容读法」——`/api/health` 是运维探针频繁消费的端点，若已有外部监控按字符串判读，切换时需双吐一个版本。
6. **C1 路由 redirect**：保留。若后续做「清理旧路径」，需先确认无外部文档引用。
7. **A4 `TOKEN→CUSTOM` / A5 `UTC` 别名**：各写一条存量扫描 SQL 确认零行后即可删除，成本低。
