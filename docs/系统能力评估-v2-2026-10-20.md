## 4. 设计约定（非缺陷，robin 2026-10-19 确认）

**折扣（DiscountPolicy）仅展示、不参与任何计算**
- `DiscountPolicy` 仅在管理台 CRUD 消费：`ModelController` / `ModelService` / `DiscountPolicyDto` / `DiscountPolicyEntity` / `DiscountPolicyMapper`。
- 计费计算路径（`knot-adapter/.../calculator/*`、`BillingService`、`BillingFactAssembler`）不含 `discount` 引用——这是**设计意图**，非缺陷。
- robin 明确：折扣仅供前端展示，**不参与任何计费 / 成本计算**。v2 初稿曾误判为 P1 正确性缺陷，特此更正（详见第 8 节）。
- **P1#4（可选清理）**：`DiscountPolicy.java:6` `double discountValue` 非 `BigDecimal`。鉴于折扣不参与计算、仅展示，精度差异仅可能影响界面显示（如 `0.30000000000000004`），不影响计费金额；列为可选整洁性清理，非阻塞项。

### 8.3（2026-10-20 00:20）— P1+P2 闭环 & 「全局请求超时缺失」误判更正

**（一）误判更正：全局请求超时其实已具备**

原第 3 节写「HC5 `setResponseTimeout` 未启用、非流式上游无总超时」，属**误判**。核实代码后确认超时体系完整：

- `UpstreamRestClientConfiguration.upstreamHttpClient` 已用 `RequestConfig.custom().setResponseTimeout(...)`（HC5 总响应超时，默认 120s）；
- `upstreamConnectionManager` 设 `connectTimeout`（5s）/ `socketTimeout`=readTimeout（120s）；
- `GatewayUpstreamClientProperties.requestBudget`（默认 600s）以 `DeferredResult` 超时形式作用于每条网关请求（`GatewayControllerSupport:87`），是唯一真总超时。

三处叠加已覆盖「建连 / 读静默 / 整段响应 / 单请求总预算」，故该项划除。

**（二）P1-MON 监控闭环**

- `knot-gateway` / `knot-admin` 引入 `spring-boot-starter-actuator` + `micrometer-registry-prometheus`。
- 新增 `org.chobit.knot.gateway.metrics.GatewayMetrics`：5 项域指标——`knot.gateway.traffic.reject`（限流/额度，按 reason 分标签）、`knot.gateway.ejection.skip`、`knot.gateway.upstream.failure`（按 code 分标签）、`knot.gateway.failover`、`knot.gateway.proxy.latency`（Timer，按 outcome 分标签，配直方图与 SLO 边界）。
- 埋点判空（`metrics != null`），与 `eventPublisher` 同款处理：观测开关不改变请求链路结构；单测构造 handler 传 null 不受影响。
- `management:` 只暴露 `health,info,prometheus,metrics`，`show-details=never`。HTTP 层吞吐/延迟由 Spring 自带 `http.server.requests` 提供。

**（三）P6 非阻塞重试闭环（结构性改动）**

- `invokeWithRetry` → `retryOnce` 改为 `CompletableFuture`；退避由 `CompletableFuture.delayedExecutor(delayMs, MILLISECONDS, gatewayAsyncExecutor)` 承载——**延迟期间不占用任何线程**，到期后重试动作回到异步池执行。原 `Thread.sleep` 与 `sleepQuietly` 已删除。
- 为真正释放线程，异步化向上贯穿：`attemptCandidates`（候选遍历改为索引递归 + `ScanState` 累加态）、`proxyWithFailover`、`proxy`、`AbstractGatewayRequestTemplate.handle/handleMap/handleMultipart` 均改为返回 `CompletableFuture`；`GatewayControllerSupport.dispatch` 用 `thenCompose(identity)` 展平。
- 异步回调跨线程，故新增 `withRequestContext(...)` 在每个回调前重新绑定 `RequestContextHolder`（流式响应头 / 首 token 头 / 测试头解析均依赖它）。
- 语义保持：在途计数（`deferredToStream` 时延迟到流写完释放）、摘除计数（候选级一次，不按重投放大）、fail-open 第二轮扫描、`GATEWAY_ERROR` 事件发布，均与原同步实现一致。
- 新增 `GatewayRequestHandlerInvokeWithRetryTest` 5 例（首试即成功 / 重试后成功 / 达上限抛末次异常 / 不可重试只试一次 / 单线程执行器下退避不阻塞）。

**（四）P2 闭环：SQL_INIT_MODE 守卫 + Dockerfile + CI**

- `SqlInitModeGuard`（knot-admin，`@PostConstruct`）：非生产 profile 放行；生产 profile 下 `spring.sql.init.mode` 为 `ALWAYS`（含未设置的默认值）即 `IllegalStateException` 拒启。与 P0-SEC 同款安全默认思路——不靠注释约束，靠启动失败逼出显式配置。
