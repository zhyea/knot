## 1. 四维度定级对比

| 维度 | v1 定级 | v2 定级 | 关键变化 |
|------|---------|---------|----------|
| 功能能力矩阵 | B+ | **B+** | P0-1 流式记账闭环、P0-2 假端点下线（两处 v1 功能性缺陷已闭环）；折扣为设计上「仅展示、不参与计算」，非缺陷 |
| 非功能与性能容量 | C+ | **C** | P10 请求体限制 / P4 防爆破 / P8 MGET / P6 异步池 改善；但**无全局请求超时、无监控指标**，容量可观测性仍为零 |
| 架构成熟度与技术债 | A- | **A-**（维持） | `GatewayAsyncConfiguration` 是实质架构改进；但 `Thread.sleep` 退避残留、默认密钥技术债已清零（P0-SEC 已修） |
| 生产就绪度 | C | **C**（维持） | Dockerfile / CI / 监控 / `SQL_INIT_MODE` 默认 `ALWAYS` 四大硬缺口均未动 |

**一句话结论**：核心链路正确性（流式记账、假端点）已闭环，安全加密、并发模型与默认密钥 fail-fast 均有实质改善；但**生产就绪度没有本质变化**——无监控、无容器化/CI、`SQL_INIT_MODE` 默认 `ALWAYS` 仍是硬缺口。当前可支撑内部联调/准生产；对外生产部署须设 `prod` profile 并注入密钥、并完成 P2 硬缺口。

## 3. 仍残留项（按严重度）

### 🟠 P1 级（唯一高优先级残留）

**P1-MON：监控指标完全缺失**
- 全仓 grep `micrometer | actuator | MeterRegistry | Prometheus | @Timed | Gauge` **无结果**。现有 `TrafficCounter*` 是业务限流计数，不导出、不可观测。
- **后果**：无 QPS / 延迟 / 错误率 / 限流命中 / 摘除事件 / 计费对账指标；生产排障与容量规划全盲。

### 🟡 P2 级 — 生产就绪硬缺口

- **Dockerfile / CI 缺失**：Glob 全仓无 `Dockerfile`、`docker-compose*.yml`、`.github/workflows/*`、`Jenkinsfile`。
- **`KNOT_SQL_INIT_MODE` 默认 `ALWAYS`**：`application.yml:16` `mode: ${KNOT_SQL_INIT_MODE:ALWAYS}`；注释要求生产设 `NEVER`，但默认值危险（每次启动重跑 schema/data）。
- **全局请求超时缺失**：HC5 5.3.1 原生 `setResponseTimeout` 未启用；流式有 600s async 兜底，但非流式上游无总超时 → 坏上游可长时间占住异步池线程。
- **P6 退避残留**：`GatewayRequestHandler.java:363/368` `Thread.sleep` 同步退避仍在（虽已搬离 Tomcat worker，但仍占异步池线程 + 加重退避税）。

## 4. 设计约定（非缺陷，robin 2026-10-19 确认）

**折扣（DiscountPolicy）仅展示、不参与任何计算**
- `DiscountPolicy` 仅在管理台 CRUD 消费：`ModelController` / `ModelService` / `DiscountPolicyDto` / `DiscountPolicyEntity` / `DiscountPolicyMapper`。
- 计费计算路径（`knot-adapter/.../calculator/*`、`BillingService`、`BillingFactAssembler`）不含 `discount` 引用——这是**设计意图**，非缺陷。
- robin 明确：折扣仅供前端展示，**不参与任何计费 / 成本计算**。v2 初稿曾误判为 P1 正确性缺陷，特此更正（详见第 8 节）。
- **P1#4（可选清理）**：`DiscountPolicy.java:6` `double discountValue` 非 `BigDecimal`。鉴于折扣不参与计算、仅展示，精度差异仅可能影响界面显示（如 `0.30000000000000004`），不影响计费金额；列为可选整洁性清理，非阻塞项。

### 8.1（2026-10-19 23:00）— P0-SEC 已闭环

- 已实测双分支：① `local` profile → 上下文正常加载（`BUILD SUCCESS`）；② 无 profile → 守卫抛 `IllegalStateException`（active profiles=[]）拒绝启动（`BUILD FAILURE`，符合预期）。
