# knot-service `gateway.service` 包类名统一方案

- 日期：2026-10-14
- 范围：`knot-server/knot-service/src/main/java/org/chobit/knot/gateway/service/`（39 个顶层类 + `external` 子包 3 类，另有一个空目录 `schedule/`）
- 性质：**仅方案，未改任何代码**

---

## 1. 结论

**可以统一，且值得做。** 现状 29 个 `@Service` 业务服务命名已基本整齐（`XxxService` / `Domain+XxxService`），真正的不统一集中在三类：**8 个 `@Component` 协作者后缀各自为政**（Support/Source/Resolver/Registry/Runner/Migrator 六种）、**2 个非 Bean 数据类型混在 service 包**、**4 个泛化或孤例命名**。全部问题均为编译期类型引用，**无按名字引用 Bean 的代码**（已全量 grep `@Qualifier`/`@Resource`/`getBean`，0 命中），重命名不触碰 Spring 注入语义与 API 契约。

## 3. 统一规范提案

### 3.1 命名纪律（建议写入项目规范）

1. **角色后缀白名单**，之外不许发明新后缀：
   - `Service` —— `@Service` 业务服务（包顶层唯一允许的后缀）
   - `Support` —— 无自身领域语义的共享校验/查找/转换协作者
   - `Source` / `Resolver` / `Registry` / `Runner` / `Provider` / `Migrator` —— 各对应一个明确契约角色（契约实现、归一化解析、只读注册表、`ApplicationRunner`、`Map<String,接口>` 策略族、启动迁移）
2. **同域多服务必须域前缀**：`Domain + XxxService`；单词域不前缀。判定法——同类超过 1 个即加前缀。
3. **禁止泛化域名**：System / Common / Base / Manager 这类什么都能装的词不作为类名主干。
4. **数据类型不进 service 包**：record DTO 归 `dto.<域>`，资源句柄/上下文随所属链路 DTO 包。
5. **接口/抽象/实现三段式**沿用 external 子包现状（`XxxProvider` 接口 → `AbstractXxxProvider` → 厂商名 `XxxProvider`）。

### 3.2 重命名映射表

| 现名 | 建议 | 理由 | 引用文件数* |
|---|---|---|---|
| SystemService | **OperationLogQueryService**（或与 OperationLogService 合并，见决策点 D1） | 具名化；与写侧 OperationLogService 域对齐 | 2 |
| AdminAuthorizationService | AuthorizationAccessService | 去孤例前缀，统一 Authorization 系；且它职责是运行时 API 访问校验（`validateApiAccess`），"Access"比"Admin"更准确 | 5 |
| TestRequestPresetService | RoutingTestPresetService | 补域前缀，对齐 RoutingRuleService / RoutingConsumerService | 2 |
| RoutingTestPreparation | `dto.routing.RoutingTestPreparation`（移包） | record DTO 归位，与 RoutingRuleDto 同域 | 5 |
| RoutingTestStreamHandle | `dto.routing.RoutingTestStreamHandle`（移包） | 与 Preparation 成对归位 | 4 |
| ProviderCredentialSupport | ProviderCredentialSupport 保留（进 support 子包或维持扁平，见决策点 D3） | Support 后缀合规，问题只在"同域多后缀"，不必改 | 3 |
| ProviderCredentialEncryptionMigrator | **删除** | no-op 死代码 | 1（仅自身） |
| `service/schedule/` 空目录 | **删除** | 死目录 | 0 |

\* 引用文件数为不含自身的 `.java/.xml` 命中文件数（已 grep 实测）。

**明确不改**：Model 系 5 个、Routing 系其余 2 个、Authorization 系其余 6 个、ProviderService/ProviderProfileService、AppService、DepartmentService、UserService/UserSettingService、ModerationWordService、PluginService、EnumConfigService、OptionsService、BillingService、NotificationService、HealthService、external 子包 3 类——已符合纪律。

### 3.3 协作者组织（决策点 D3 的二选一）

- **方案 a（推荐）**：8 个协作者原样保留扁平，仅把"角色后缀白名单"写成纪律。改动最小，零 import 地震。
- **方案 b**：8 个协作者移入 `service.support` 子包。导航更清，但 8 个类 + 约 30 个引用文件的 import 全量变更，回归面最大。

## 4. 影响面与风险（已实测）

| 检查项 | 结果 |
|---|---|
| 按名引用 Bean（`@Qualifier`/`@Resource`/`getBean`/SpEL） | **0 命中**（knot-service + knot-admin 全量 grep）→ 重命名只动类型引用，Spring 按类型注入不受影响，bean 名静默变更 |
| AOP pointcut 按包名/类名字符串匹配 | 无。`OperationLogAspect` 仅 import OperationLogService（类型引用，IDE 重构安全） |
| API 契约 / 前端 | 零影响。控制器路径、请求响应结构不动，前端不改 |
| MyBatis mapper XML | 无服务类名字符串出现（grep `.xml` 无命中） |
| 测试 | 11 个测试类需同步改名/移包：AdminAuthorizationServiceTest、EnumOptionRegistryTest、ModelFamilyResolverTest、ModelServiceTest、ModerationWordServiceTest、OptionsServiceTest 等 |
| 门禁 | `mvn -f knot-server/pom.xml -pl knot-service,knot-admin test`（定向 reactor，绕开其他模块）；重命名不触前端，无需 vue-tsc |
