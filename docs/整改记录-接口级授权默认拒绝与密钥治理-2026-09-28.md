## 3. 关键实现要点

### 3.1 授权默认拒绝

- `AdminAuthorizationInterceptor.preHandle`：删除 `@AuthCheck` 判定分支，凡 `HandlerMethod` 一律走
  `AdminAuthorizationService.validateApiAccess`（`knot-admin/.../auth/AdminAuthorizationInterceptor.java:31-43`）。
- `WebMvcConfig`：白名单新增 `/api/common/enums`（全站字典），其余维持 login / force-password-change /
  logout / health / me-authorizations（`knot-admin/.../config/WebMvcConfig.java:37-49`）。
- 既有 `@AuthCheck` 注解保留为语义标注，不再决定拦截行为。

### 3.2 权限与绑定种子数据（脚本化生成）

新增 `.workbuddy/audit/gen_api_bindings.py`：解析 30 个 admin Controller，按
`@OperationLog.operation` > 路径末段 > 方法名 > HTTP method 的优先级推断动作，生成：

- `ks_permissions`：**新增 65 条**（id 58-122），复用既有 57 个权限码，零重复
- `ks_api_permission_bindings`：**新增 101 条**（id 54-154），覆盖全部 126 个 endpoint（白名单除外）
- `ks_role_permissions`：OPERATOR(2) 授予全部新增权限；DEVELOPER(3) 仅授予只读类（view）

落库实测：permissions 122、bindings 154、ADMIN 122（CROSS JOIN 自动全量）、OPERATOR 112、DEVELOPER 28。

新增接口 SOP：改完 Controller 后执行

```bash
python .workbuddy/audit/gen_api_bindings.py          # 打印 endpoint → 权限码映射，人工审一遍
python .workbuddy/audit/apply_bindings.py            # 追加到 data.sql（自动置于权威授权块之前）
```

> 默认拒绝的代价：**新增接口若未补绑定，登录用户一律 403**。上线前必须跑一次上面的脚本。

### 3.3 密钥与口令

- `JwtUtil`：密钥改从 `KNOT_JWT_SECRET` 环境变量 / `knot.jwt.secret` 系统属性读取，长度不足 32 直接抛异常，
  命中开发默认值打印 WARN（`knot-common/.../auth/JwtUtil.java:26-60`）。
- `CredentialProperties`：开发默认值提取为 `DEV_DEFAULT_KEY` 常量并提供 `isDevDefaultKey()`；
  `CredentialEncryption` 构造时命中即 WARN。gateway 侧补齐 `knot.credential.encryption-key`，保证与 admin 同源。
- 库账号口令改 `${KNOT_DB_USERNAME}` / `${KNOT_DB_PASSWORD}` 注入；`spring.sql.init.mode` 改
  `${KNOT_SQL_INIT_MODE:ALWAYS}`，生产设 `NEVER` 即可关闭每次启动的 schema/data 初始化。
- `UserService.resetPassword`：删除硬编码 `12345678`，改为 `SecureRandom` 生成 12 位一次性口令，
  经新增 VO `ResetPasswordResult` 只在本次响应返回；前端改为弹窗展示一次性密码。
  同步删除 login 的「默认密码 → 强制改密」分支（已无默认密码）。
